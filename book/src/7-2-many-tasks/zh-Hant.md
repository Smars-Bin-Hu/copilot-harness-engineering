讀這一章，你需要讀過 [慎用子 agent](2-3-subagents.html) 和 [管任務，不管對話](5-1-tasks.html)。

## 一句話 {#in-one-sentence}

要同時管十件事，就跑十個獨立的任務，每個任務一個 agent，只在門的地方叫人。按任務拆，不按檔案拆。任務裡唯讀的工作，仍然可以交給子 agent。

## 給主管 {#for-leaders}

- **要做的決定**：決定人可不可以同時跑好幾個任務、一開始跑幾個、在哪裡叫人。
- **風險**：限制是人的注意力，不是 agent 的數量。一道永遠不讀就批准的門，只是裝飾。我沒有淨加速的證據：我沒有量過十個任務並行，對比十個一個接一個。
- **做對的成本**：用量隨任務數成長（十個任務，十倍的用量），再加上一個看板，或一份簡單的等待清單。從兩三個開始。
- **可以問團隊**：「現在有哪些任務在等人，等多久了？如果其中兩個改了同樣的檔案，會怎樣？」

## 問題 {#problem}

agent 在你不在的時候可以做很多事。所以下一個念頭是：一個 agent 好用，為什麼不同時跑很多個？這個念頭有兩種讀法，只有一種行得通。

**第一種是一個大工作，很多個 agent**。你交出一個大任務，由協調者把它分給一組 agent，每個有一個角色（計畫、實作、檢查）。這看起來像公司的組織圖。這就是 [慎用子 agent](2-3-subagents.html) 測過的設定：交接會丟掉理解，同樣的檔案被每個 agent 再讀一遍。那一章並不反對為一個任務的每一步，用一個新的工人。它反對的，是好幾個 agent 同時改同樣的檔案，因為那時就得有人去合併它們的工作。

**第二種是很多個工作，每個一個 agent**。十個人提的十個要求，或你自己的十個不同問題。每一個都是獨立的一件工作，有自己的資料夾、自己的 agent、自己的終點線。它們之間不共用任何東西，所以不需要合併。

這一章講的是第二種。它不聰明，卻是讓一個人能同時讓十件事前進的辦法。

缺的不是 agent。是你。agent 可以等人好幾個小時，不用任何運算。但它等的時候帶著的東西會過期：對話的快取過期了，等你回答時，倉庫可能已經往前走了。人也沒辦法等十個 agent，而不弄丟線索。所以設計的問題是：怎麼把一個人的注意力，分配在十個任務上？

## 原理 {#how-it-works}

### 並行在任務之間，不在一個任務裡面

每個任務是一個資料夾，就像 [管任務，不管對話](5-1-tasks.html) 講的：需求、計畫、待辦清單和交接檔，全都放在檔案裡。一個 agent 會話一次拿著一個任務。十個任務就是十個資料夾、十個會話。

::: figure 7-2-ten-lanes

為什麼這樣拆得乾淨，而一個大工作的拆法拆不乾淨：

- **沒有共用的東西**。每個任務有自己的資料夾，所以兩個 agent 絕不會在同一刻編輯同一個檔案。任務裡面沒有合併，因為只有一個寫的人。
- **每個任務是完整的**。做事的 agent 也拿著計畫和上下文。沒有從理解的 agent，交給必須動手的 agent 的交接。那正是三角色測試裡的成本。
- **交接是一個檔案，不是一則訊息**。如果一個任務停了一天，接手的人讀資料夾就行。

agent 之間不互相說話。唯一在任務之間來往的，是你。

### 任務什麼時候需要人

現在是要緊的問題：任務什麼時候需要你？如果答案是「常常，而且不可預測」，十個任務會吃掉你一整天。所以設計把每一次需要人的時候，推到少數固定的點，也就是**門**。門是 agent 停下來，等人說好的地方（細節在 [兩道門：人在哪裡批准](5-3-two-approvals.html)）。

任務只因為這類理由等你：

- 第一道門：需求寫好了，計畫也準備好了，兩者都在等你確認和批准；
- 第二道門：寫回（把做完的改動複製進倉庫）在等你的批准；
- 寫入做到一半失敗了；
- 它需要一次只有你能做的運行的結果；
- 它的獨立檢查用完了，由你決定下一步；
- agent 停了，或一次無人值守的執行結束了。

在這些點之間，agent 在工作，不需要你。這就是整個想法：**只在門的地方叫人**。一個「偶爾，有問題的時候」就需要你的任務，是最糟的情況，因為你沒辦法圍繞它安排時間。只在指名的點上提問的任務，是可以排進行程的。

這也告訴你要建什麼。任何讓 agent 因為不是門的理由而停下來的東西，都是你注意力的漏洞：模糊的要求、缺少的權限、一個為無害動作跳出來的確認框。每一個都值得移除（[詢問不是限制](4-2-ask-vs-refuse.html)）。

### 碰同一份程式碼的任務

這是常見的情況，所以放在前面。分開的任務資料夾，不等於分開的倉庫。兩個改同樣檔案的任務，在寫回的時候會碰到。一種設計的辦法：讓每個任務有自己的分支或工作副本（git worktree 是一種辦法），讓寫回檢查它碰的檔案從任務開始後有沒有變，如果變了，就停下來問人。一次寫回一個任務。我沒有測過十個任務同時改一個倉庫，所以這種事有多常咬人，我說不上來。

### 注意力是貴的部分

跑十個任務，不會讓你快十倍。它把你的時間移到門上，而門只有在你讀了它的時候才有價值。

- **讓每一道門都容易讀**。你批准的計畫，應該放得進一頁，在編輯器裡，不是在終端機裡捲動。你確認的需求，也應該是一頁（[需求由 agent 寫，人確認](5-2-requirements.html)）。如果讀它要二十分鐘，你就會略讀，而略讀的批准又回到「點允許」的問題。一個值得看的數字是，你多常拒絕或修改計畫：如果從來沒有，你可能是在略讀。
- **不要拿超過你讀得完的**。你能跑的任務數，由你讀計畫和 diff 的速度決定，不是由螢幕放得下幾個會話決定。從兩三個開始。你能拿好幾個，取決於任務，我沒有量過。
- **把類似的門放在一起**。如果有三份計畫在等，一次坐下來全讀。在計畫、diff 和需求之間切換，比讀三份計畫更花力氣。
- **成本會累加**。十個任務是十倍的用量，所以每個任務都要有一條停止規則（[無人值守：什麼時候必須停](5-7-when-to-stop.html)）。一個等你的時間超過 prompt 快取存活時間的任務（在 Anthropic 的 API 上是五分鐘或一小時，見 [選模型：算的是每次成功的成本](1-1-models-and-cost.html)），你回來時，它得付全額價格再讀一次它的上下文。Copilot 在這方面怎麼表現，我沒查過。

### 一份等你的清單

開著十個會話，你怎麼知道哪一個在等？一個一個視窗去翻，正是你想避免的成本。

答案是**看板**：一頁，列出每一個還開著的任務、它在等什麼、等了多久。有兩個設計重點讓它可信。

::: figure 7-2-board

- **狀態由程式寫，不是由 agent 寫**。agent 停下來時，一個 hook 會執行，記下「在等你」。看板從一個給機器讀的檔案讀這個狀態。它不讀 agent 用散文寫的進度筆記，因為 agent 會忘了打勾，或打太多勾。
- **等待是一個數字**。一個任務開始等待之後經過的時間，告訴你該先打開哪一個。

同一頁上有一個開關，我在一天結束時用。它把每個 agent 沒在做的開著的任務暫停，隔天早上再接回來。暫停期間的等待時間不計，所以數字保持誠實。

**沒有看板？用清單**。這個想法手動也行：每個任務一個終端機分頁，用任務命名，再自己記一張短清單，寫哪個分頁在等、等了多久。

### 任務裡的唯讀幫手

一個任務一個 agent 的規則，講的是會寫入的工作。在一個任務裡，只讀的幫手仍然可以並行，並交回簡短的摘要，因為沒有幫手會改檔案（[慎用子 agent](2-3-subagents.html)）。每個任務一個寫的，讀的則依讀取的價值，要多少有多少。

## 代價和陷阱 {#costs-and-traps}

**切換上下文是你的事**。agent 不介意切換。你介意。十個任務在十個不同的領域，比十個在同一個領域，花更多注意力，因為每道門需要不同的知識。

**永遠是「好」的門，就是你不讀的門**。如果你連續批准十份計畫，一份都沒打開過，那些門就是裝飾。解法是更少、更小的門，不是更多。

**看板只和它的狀態一樣好**。如果狀態來自 agent 自己的話，看板就會說謊。這就是狀態來自 hook 和檔案的原因。

**我沒有拿它和其他辦法比較過**。我沒有淨加速的證據：我沒有量過十個並行任務，對比十個一個接一個，或對比一個團隊。論點是結構：沒有共用的東西，人的注意力是極限。標題裡的「十」是一個例子，不是結果。

## 什麼時候可以刪掉 {#when-to-delete-it}

看板存在，是因為會話不會告訴你它在等。平台如果在一個地方，顯示每個執行中的 agent 會話，和各自在等什麼，看板就可以拿掉。Copilot 在這件事上做到哪裡，我沒查過。

想法不會拿掉。就算由平台來列出，拆法還是留著：每個任務一個寫的，人在門的地方被叫來。

## 在你自己的環境試試 {#try-it}

不用裝 harness。在你自己的倉庫裡打開 agent，貼上：

::: prompt
只用唯讀的 git 指令，列出這個倉庫裡有最近 commit 的分支、worktree 和開著的 pull request。對每一個，列出它相對於主分支改了哪些檔案。然後找出改同樣檔案的配對，說明如果一起寫回，哪些會衝突。對每一件工作，說明它大概在等什麼（審查、一個決定、一次測試運行）。不要改任何檔案。
:::

::: prompt
/harness-rookie-wondering 我讀完了「同時管十件事」這一章。請教我這個 harness 怎麼讓一個人跑好幾個任務：任務資料夾、任務可以等待的各種狀態，以及看板怎麼知道一個任務在等。帶我打開真實的檔案，讓我看看板讀什麼、誰寫它。
