這一章接著 [慎用子 agent](2-3-subagents.html) 裡的無人值守的執行往下講：一個 hook 讓 agent 在沒人看著的時候，沿著待辦清單一直做下去。那一章講的是這樣的執行怎麼跑起來，這一章講它怎麼結束。

## 一句話 {#in-one-sentence}

無人值守的 agent，只會走到停止規則管得到的地方。所以要事先把規則設好，設成總預算，而不只是步數，同時還要防著它太早宣布「做完了」。

## 給主管 {#for-leaders}

- **要做的決定**：批准無人值守的執行之前，先設好它的停止規則，要設成總預算，不只是步數，並要求每次停止都交回一個原因。
- **風險**：你一離開，就不再是那條停止規則了。這次運行可能繞上好幾個小時，可能把一整晚的用量花在一個不可能成功的步驟上，也可能太早停下來，還說自己做完了。我的設定有步數和時間的上限，但還沒有總預算，我也把無人值守的執行稱為 beta。無人值守的執行是否勝過有人看到最後，我沒有量過。
- **做對的成本**：每個任務幾條規則，加上一個預算數字。規則收得緊，代價是停得更多，早上要有一個人待命。反過來，交回的東西要是含糊，花的時間比在旁邊看著還多。
- **可以問團隊**：「如果這個整晚在跑，結果出了問題，什麼會讓它停下來？早上我會看到什麼？」

## 你離開以後，誰來喊停？ {#problem}

你看著 agent 的時候，你就是它的停止規則。看到它出錯，你就按停止。可是你一離開，這條規則也跟著你走了，剩下的只有你離開前寫下來的東西。

所以對無人值守的執行，該問的不是「它會成功嗎？」，而是「它不成功的時候會怎樣？」它可能繞上好幾個小時，也可能把一整晚的用量花在一個不可能成功的步驟上。碰到只有你能做的選擇，它可能自己就做了決定。它也可能反過來，太早停下來，說自己做完了。

這幾種情況各需要一條不同的規則，而且都得在你離開之前設好。歸納起來是三個問題：它什麼時候必須停？停下來時交回什麼？我們怎麼知道它真的做完了？

## 什麼時候停、交回什麼、怎樣才算真的做完 {#how-it-works}

::: figure 5-7-stop-points

### 每條停止規則，抓一種出錯的方式

第一個問題，什麼時候必須停，答案不只一個，因為每一條停止規則抓的是運行出錯的一種方式。這些規則有一個共同的原則：**由程式根據事實來判斷，不是由 agent**。卡住的 agent，最沒資格判斷自己是不是卡住了。

其中三條你已經在 [慎用子 agent](2-3-subagents.html) 裡見過，分別是步數和時間的上限、一次運行中圍欄拒絕 agent 兩次就停止、沒有任何一步被勾掉就停止，具體的數字也在那一章裡。（**一步**是待辦清單上的一項。這條停止規則不是 [保護規則本身的檔案](4-3-guardrails.html) 裡的斷路器，斷路器處理的是一個會話裡同一個拒絕一再重複。）那些是我設定裡的數字，只是例子，不是什麼定論：是我選的，我也沒有量過它們對不對。

另外兩條，同樣可以根據事實來判斷。一條是計畫變了。人批准的是一份計畫，這次運行只被允許執行那份計畫，所以計畫一變，授權立刻失效。另一條是檢查用完了：獨立檢查一直失敗，直到碰上它的上限（[讓「通過」可信](5-5-counted-checks.html)）。

最後一種不一樣，因為有些停止是事實顯示不出來的。比方說兩張表對同一個欄位的定義不同，計畫又沒說該用哪個，這一點只有 agent 看得到。所以它可以自己停下來，但必須附上原因，而且只限於需要人的情況，不能為了小選擇就停。

### 預算是總量，不是次數

上面這些規則數的都是東西，不是步數就是拒絕次數。可是你真正擔心的是**花費**，而次數限制不了花費。二十個小步驟和二十個各自啟動幫手的步驟，帳單根本不是一回事。

能限制花費的是**預算**，也就是對用量和時間的一個總量，把主 agent 和它所有的幫手合在一起算。幫手拿到的是剩下的部分，不是自己另有一份新的額度。用量和時間，只要越過其中一條線，運行就停止。

我自己的設定還沒有這個（它有上面那些次數限制和一個時間上限），不過可以這樣建。由人設一個任務層級的預算，用量和分鐘數各一個。每一步之前，一個 hook 從平台自己的會話紀錄，把主會話和每個幫手會話的用量加起來，到了那條線就停止運行，並把「budget」寫成原因。至於幫手的用量會不會及時出現在紀錄裡、讓它來得及據以停止，我沒有檢查過。

而且，按用量算的預算，並不完全等於按錢算的預算：供應商快取過的輸入，讀取的價格大約是基本價格的十分之一（[選模型：算的是每次成功的成本](1-1-models-and-cost.html)），只是 Copilot 怎麼計費，我沒有檢查過。

有些工具已經為非互動的執行提供了簡單的版本。Claude Code 有 `--max-turns` 和 `--max-budget-usd`（我自己沒試過），兩者都只用於 print 模式（`claude -p`）。金額上限是拿用戶端的估計值來比對，不是你的帳單，而且可能被超過。子 agent 的花費也算進去，一旦達到上限，就不能再啟動新的子 agent（[CLI reference](https://code.claude.com/docs/en/cli-reference)）。

### 回來的人該看到什麼

不管是哪條規則觸發的，回來的人面對的都是一次已經停下來的運行。它要是不說原因就停了，留給人的就是一個謎。所以一次停止要交回三樣東西：

1. **為什麼停止**，用一個人能據以行動的詞：budget、refused、no progress、needs a decision。
2. **現在在哪裡**：做完的步驟、它正在做的那一步，以及工作的狀態。
3. **人要決定什麼**，用一句話。

在我的設定裡，根據事實停止時，原因由程式寫，而 agent 自己停止時，則由 agent 寫一句話。那一句話的指令是：哪一步卡住、為什麼、你必須決定什麼。只寫「遇到了問題」是不夠的。

agent 一路上做過的決定也很重要。計畫沒定、由 agent 選的任何事，它都要寫一行，說明選了什麼、為什麼。這份紀錄，人回來時會讀，無人值守的工作也正是靠它才能被審查。

### 「做完了」說得太早

前面擔心的，都是該停的時候不停。反方向的失敗一樣真實：運行停得太早，還說自己做完了。Anthropic 在一個長時間運行的寫程式 agent 上描述過這種情況：「後來的 agent 實例會看一圈，見到已經有進展，就宣布工作完成」（[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)）。

說到底，停下來本來就是交給 agent 的事，所以它說「做完了」是有來由的。正因為這樣，運行能不能結束，要看程式能核對的事實，不看 agent 怎麼說：

- **清單上的每一步都勾了**。
- **獨立檢查通過了**，由程式計數，針對工作目前的版本。
- **計畫就是被批准的那份**。
- **寫回的計畫已經做好**，給人讀（[兩道門：人在哪裡批准](5-3-two-approvals.html)）。

到這時，「做完了」才是一個狀態，不是一個說法。

即使這樣也不是密不透風，因為 agent 可以勾掉一步卻沒做完。檢查者在最後讀整個結果，人讀整份 diff，但程式裡沒有任何東西證明第 7 步真的做了。所以我把勾當成說法，把運行結束時的檢查當成算數的東西。

## 安全的代價，和停止規則做不到的事 {#costs-and-traps}

這些規則讓運行更安全，但不是免費的。規則越多，能一口氣跑完的晚上就越少：收得緊的運行，很多個晚上都會中途停下，交回的東西不多，早上得有人待命接手。安全的代價就落在這裡。無人值守的執行是否比有人看到最後更好，我沒有量過，所以它在我的設定裡還被稱為 beta。

停止也不等於有了答案：每一次停下來，留下的都是做了一半的工作。在門上拍下的快照（[兩道門：人在哪裡批准](5-3-two-approvals.html)），能讓人看到運行停下來時的狀態。即使如此，交回的內容要是含糊，人反而得花比在旁邊看著更多的時間。

不過，有些工作根本不該無人值守，不管停止規則多好都一樣。[兩道門：人在哪裡批准](5-3-two-approvals.html) 的那三個點在這裡同樣適用：花真錢的、授予權限的（例如寫入共用的倉庫）、無法復原的工作，都需要人。

還有一個陷阱是留給 agent 的，不是留給你的：為了避開拒絕而繞路。拒絕是系統在說：這一步超出了範圍。所以我給 agent 的規則是：照原因說的改一次，還是不行，就停下來。

## 什麼時候刪掉這些規則，什麼會留下 {#when-to-delete-it}

這些停止規則之所以存在，是因為平台沒有提供它們。如果平台給你一個涵蓋整次運行、包括幫手的總預算，就用它。不管怎樣，根據事實停止的想法都會留下：agent 的「我做完了」不是終點線。
