这一章接着[慎用子 agent](2-3-subagents.html)里的无人值守的运行：一个 hook 让 agent 在没人看着的时候，沿着待办清单一直干下去。那一章讲了它怎么跑，这一章讲它怎么收场。

## 一句话 {#in-one-sentence}

无人值守的 agent，只能走到它的停止规则管得到的地方。要提前把规则设好，用总预算，而不只是步数；还要防它过早宣布“做完了”。

## 写给管理者 {#for-leaders}

- **要拍板的事**：批准无人值守的运行之前，先把它的停止规则设好，用总预算，而不只是步数，并要求每次停下都交回原因。
- **风险**：你一走，就不再是那条停止规则了。运行可能循环好几个小时，可能在一个注定成不了的步骤上烧掉一晚上的用量，也可能提前停下，还说自己做完了。我的配置有步数和时间的限制，但还没有总预算，我把无人值守的运行叫作 beta。无人值守的运行是否比人盯到最后更好，我没有测过。
- **做对的代价**：每个任务几条规则，加一个预算数字。规则收得紧的代价，是停得更多，早上得有人待命。含糊的交回，比盯着看更费时间。
- **可以问团队**：“如果这个任务通宵跑、中途出了问题，什么会让它停下来？我早上会看到什么？”

## 问题 {#problem}

你盯着 agent 的时候，你就是停止规则。你看到它跑偏了，就按停。你一走，这条规则也跟着走了。剩下的，只有你走之前写下的东西。

所以，对无人值守的运行，问题不是“它行不行”，而是“不行的时候会怎样”。它可能循环好几个小时。它可能在一个注定成不了的步骤上，烧掉一晚上的用量。它可能遇到只有你才能做的选择，却自己做了决定。它也可能反过来：提前停下，还说自己做完了。

这几种情况各需要一条不同的规则，而且要在你走之前设好。有三个问题：什么时候必须停，停下时交回什么，以及怎么知道它真的做完了。

## 原理 {#how-it-works}

::: figure 5-7-stop-points

### 1. 停止规则的种类

每条规则抓一种运行出错的方式。它们的共同点是：**由代码根据事实来判断，不由 agent 判断**。一个卡住的 agent，最没资格判断自己是不是卡住了。

- **三条基本规则**。步数和时间的上限；一次运行里护栏拒绝了 agent 两次就停；没有任何一步被勾掉就停。它们和具体数字都在[慎用子 agent](2-3-subagents.html)里。（**一步**是待办清单上的一项。这条停止规则不是[保护规则本身的文件](4-3-guardrails.html)里的熔断器，那个熔断器针对的是同一个会话里同一次拒绝反复出现。）
- **计划变了**。人批准的是一份计划，运行只被允许执行这份计划。计划一变，授权立刻失效。
- **检查次数用完了**。独立检查一直不通过，达到了它的上限（见[让“通过”可信](5-5-counted-checks.html)）。
- **agent 说它走不下去了**。有些停止，事实显示不出来：两张表对同一个字段的定义不一样，计划里没说用哪个。只有 agent 看得到这一点。所以它可以自己停，但必须写明原因，而且只限于需要人的情况，小事不行。

以上是我配置里的数字。它们只是例子，不是什么真理：是我选的，我没有测过它们是不是合适。

### 2. 预算是总量，不是次数

上面的规则数的是东西：步数和拒绝次数。但你怕的是**花费**。次数限制不了花费。二十个小步骤，和二十个每步都启动帮手的步骤，账单不一样。

**预算**是对用量和时间的一个总量，把主 agent 和它所有的帮手合在一起算。帮手拿到的是剩下的部分，而不是自己另有一份额度。越过第一条线，运行就停。

下面是一种搭法；我自己的配置还没有（它有上面那些次数限制和一个时间限制）。由人给每个任务设一个预算，用量和分钟数各一个。每一步之前，hook 根据平台自己的会话记录，把主会话和每个帮手会话的用量加起来。到了线，就停下运行，把“预算”写成原因。帮手的用量能不能及时出现在记录里、赶得上叫停，我没有查过。

用量也不等于钱：服务商已缓存的输入，读取价格约是基础价格的十分之一（见[选模型：看每次成功的成本](1-1-models-and-cost.html)）。Copilot 怎么计这部分，我没有查过。

有些工具已经为非交互的运行提供了简单的版本。Claude Code 有 `--max-turns` 和 `--max-budget-usd`，都只用于 print 模式（`claude -p`）。金额上限对照的是客户端的估算，不是你的账单，可能被超过；子 agent 的花费也算进去，一旦达到上限，就不能再启动新的子 agent（见 [CLI reference](https://code.claude.com/docs/en/cli-reference)）。我没有试过。

### 3. 停下时交回什么

一次不说明原因就停下的运行，是留给回来的人的一个谜。所以停下时必须交回三样东西：

1. **为什么停**，用一个人能据此行动的词：预算、被拒绝、没有进展、需要决定。
2. **走到哪了**：做完的步骤、正在做的那一步，以及工作的状态。
3. **人要决定什么**，一句话。

在我的配置里，由事实触发的停止，原因由代码写；agent 自己停的时候，由它写一句话。这句话的指令是：哪一步卡住了，为什么，你要决定什么。“遇到了问题”不够。

它一路上做的决定也很重要。计划没定、由 agent 自己选的每一处，它都写一行：选了什么，为什么。这是人回来时读的日志，也是无人值守的工作能被复核的原因。

### 4. 防止过早说“做完了”

另一边的失败同样真实。Anthropic 在一个长时间运行的编程 agent 上描述过：“后来的 agent 实例四下看看，发现已经有了进展，就宣布任务完成”（[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)）。

agent 有理由说自己做完了：停下就是别人要它做的。所以运行不该在 agent 说“做完了”的时候结束。清单上的一个勾，本身也只是一个声明（下面几段会讲），所以运行的结束要看事实：

- **清单上的每一步都勾掉了。**
- **独立检查通过了**，由代码计数，针对的是工作现在的这个版本。
- **计划就是当时批准的那一份。**
- **写回计划已经做好**，供人阅读（见[两道门：人在哪里审批](5-3-two-approvals.html)）。

到这时，“做完了”才是一种状态，而不是一个声明。

这并不严密。agent 可以不完成就勾掉一步。检查者在最后读整个结果，人读整个 diff，但没有任何代码能证明第 7 步真的做了。我把勾当作声明，把运行结束时的检查当作算数的东西。

## 代价和坑 {#costs-and-traps}

**规则越多，赢得越少**。停止规则收得紧的运行，会在很多个晚上停下来，交回的东西很少。安全的代价，是早上得有人待命。无人值守是否比人盯到最后更好，我没有测过。在我的配置里，正是因为这个，它仍然叫 beta。

**停下不等于有了答案**。运行停了，活只做了一半。在关卡处拍下的快照（见[两道门：人在哪里审批](5-3-two-approvals.html)），是人查看它停下时状态的地方。如果交回的内容含糊，花在人身上的时间比盯着看更多。

**有些活根本不该无人值守**。[两道门：人在哪里审批](5-3-two-approvals.html)里的三点在这里同样适用：花真钱、授予权力（比如写入共享仓库）、或者无法撤销的活，不管停止规则多好，都需要人。

**别为了躲开拒绝而绕路**。拒绝，是系统在告诉你这一步超出范围。我给 agent 定的规则是：按理由说的改一次；还不行，就停。

## 什么时候可以删掉 {#when-to-delete-it}

这些停止规则存在，是因为平台没有提供它们。如果平台提供覆盖整个运行（包括帮手）的总预算，就用平台的。基于事实来停的想法还在：agent 说的“我做完了”不是终点线。

## 在 harness 里探索 {#explore}

停止规则、决定每次停止的事实，以及 agent 自己停下时写的内容，都在 Copilot Harness 里跑着（那里的无人值守的运行是 beta）。针对帮手的预算还没有做。其余的，harness 可以从内部教你，配上真实的文件。按上面的说明准备好之后，输入：

::: prompt
/harness-rookie-wondering 我读完了“无人值守：什么时候必须停”这一章。请教我这个 harness 的无人值守的运行（autorun）是怎么决定什么时候停的（主题 11 和 15）：有哪些停止原因，每一个由谁来判断，以及交回什么。和我一起打开真实的文件，并画出各部分是怎么拼在一起的。
:::

它一次只教一小块，停下来确认你跟上了，再和你一起打开文件。
