讀這一章，你需要讀過 [agent 循環，和你能插手的地方](2-1-agent-loop.html)，或者知道 agent 是靠要求工具呼叫來運作的。

## 一句話 {#in-one-sentence}

hook 是平台在每一輪的固定位置執行的程式碼，子 agent 裡面也一樣。硬規則就放在這裡。它看到的是呼叫，不是指令執行起來會做什麼。

## 給主管 {#for-leaders}

- **要做的決定**：決定哪些規則必須每次都成立，把它們放進 hook（平台在每次工具呼叫時執行的程式碼），不放在 prompt 裡。
- **風險**：hook 看到的是呼叫的文字，不是指令執行起來會做什麼。它也可能悄悄失效。依我 2026 年 10 月看到的 Copilot，逾時的 hook 算通過，啟動不了的 hook 會擋掉所有工具。在一台機器上的一小批樣本裡，大約三分之一的 prompt 到達模型時，沒有 hook 本來要加上的規則；把它讀成「很多」，不要當成比率。
- **做對的成本**：一個小程式和一個設定檔，放在程式碼審查之下。我的通常在幾十毫秒內執行完。
- **可以問團隊**：「hook 很慢或壞掉的時候，我們的規則會怎樣？我們怎麼知道模型真的收到了它們？」

## 問題 {#problem}

你寫了一條規則：「絕不要改設定資料夾裡的檔案」。agent 遵守了九次。第十次，它做任務做得很深，上下文很長，規則離得很遠。它改了那個檔案。規則只是一句話，模型可以把它和其他句子放在一起權衡，這一次它把它權衡得比較低。

你需要的是一個不靠模型的記憶或心情的東西：一段每次工具呼叫都必須經過、說「可以」或「不行」的程式碼。這就是 **hook**。

hook 是你寫、由平台在固定時刻替你執行的小程式。平台交給它一段 JSON（一種表示資料的純文字格式），說明發生了什麼事，例如「agent 想執行這個指令」。hook 也用 JSON 回答。然後平台依照答案行動。模型不執行 hook，也沒辦法跳過它。

我的第一課，來自一個沒有作用的 hook。我用一個 hook，在每個 prompt 開頭，把 harness 的規則放到模型面前。它每次都執行，輸出看起來也對。但我去看模型實際收到什麼時（2026 年 10 月，一台機器上的一小批 prompt），大約三分之一裡面沒有規則。確切的數字我沒有留，所以把「三分之一」讀成「很多」，不要當成比率。VS Code 會在 prompt 裡加上它自己的提醒，它們占掉了 hook 用的那個位置。hook 回傳了對的答案，卻什麼也沒發生。我的修法，是在文字送給模型之前的最後一點，加上第二道檢查，那裡看得到整段文字，規則不在就補回去。

這一課適用於每個 hook：**檢查模型真正收到什麼，不是 hook 回傳什麼**。這一章其餘的部分，講 hook 能做什麼、怎麼失效，以及它看不到什麼。

## 原理 {#how-it-works}

### 那些時刻

::: figure 2-2-hook-points

平台提供一份時刻的清單。下面是我用的，名字是 VS Code 在它的文件裡給的。

| 時刻 | 發生什麼 | 我拿它做什麼 |
| --- | --- | --- |
| 會話開始 | 新的對話開始 | 把這個會話的基本事實給模型 |
| 送出 prompt | 你按了 Enter | 加上規則；記下這是哪個任務 |
| **工具呼叫之前** | 模型提出了要求；什麼都還沒執行 | **拒絕一次呼叫**。每條硬規則都在這裡 |
| 工具呼叫之後 | 工具已經執行了 | 留下紀錄；加一則備註 |
| 子 agent 開始或結束 | 幫手 agent 開始或結束 | 把它的包裹交給它；記下結束 |
| agent 快要停下來 | 模型寫出了回答 | 還有工作沒做完，就說一次「還沒」 |

只有工具呼叫之前這個時刻，能拒絕某一個具體的動作。它有規則需要的那樣東西：呼叫已經存在，但還沒發生。其他時刻能看、能記錄、能加文字。（停止的時刻也可以說「還沒」，見下面，但那不是拒絕一個動作。）你可以用這一章結尾的小測試，自己看到這些時刻。

### 什麼進去，什麼出來

hook 收到 JSON：這是哪個事件、哪個會話，如果是工具呼叫，還有工具名稱和它的參數。下面是從 VS Code 記錄下來的真實樣本，是一個指令執行完之後，hook 收到的東西：

::: code harness .harness/eval/fixtures/hooks/copilot-sdk/payloads/PostToolUse.Bash.json L1-L15 "hook 在終端機指令之後收到的東西：事件、工具名稱、參數和結果。"

hook 用 JSON 回答。真正有用的答案只有三種：

- **放行**。（空的答案算沒意見。平台正常的權限檢查仍然適用。）
- **拒絕，附上原因**。呼叫不會執行。原因會顯示給模型和你看。
- **加幾句話**給模型讀：一則提醒、一行狀態。

在停止的時刻還有第四種：擋下這次停止，附上一個原因，原因會像新的 prompt 一樣餵回給模型。我每次停止只允許這樣做一次。每次停止都擋的 hook，會讓 agent 永遠跑下去，而你要為每一輪付錢。

**原因是設計的一部分**。寫清楚為什麼被拒絕、該改做什麼，不然 agent 會再試同一件事，或更糟的事（[詢問不是限制](4-2-ask-vs-refuse.html)）。

### hook 出錯的三種方式

hook 是軟體。它會出錯。平台那時怎麼處理，決定了你的規則是圍欄還是裝飾。

| 發生什麼 | Copilot 怎麼做（我在 2026 年 10 月觀察到的，也是 VS Code 文件說的） |
| --- | --- |
| hook 執行了並拒絕 | 呼叫被擋下，原因顯示出來。在預設模式，以及跳過權限提示的模式下都有效。 |
| hook 啟動不了（例如寫它用的語言沒裝） | 當成拒絕：沒有任何工具能執行，畫面上也只說「hook errored」之類的話。 |
| hook 花太久 | 當成通過，而且沒有任何通知。VS Code 文件說，它會落到正常的權限檢查。 |

所以同一種失敗，可能把你鎖在外面，也可能讓門開著，取決於它怎麼失敗。你想要哪一種，是設計的選擇。該選什麼，以及我選了什麼（放行這次呼叫並記錄錯誤，最近最慢的一次呼叫接近時間上限時發出警告），是 [把執行層當軟體來設計](4-4-enforcement-design.html) 的主題。

### 在子 agent 裡面

子 agent 是為了一部分工作而啟動的第二個 agent（[慎用子 agent](2-3-subagents.html)）。它在自己的會話裡執行。在今天的 Copilot 裡，它的工具呼叫也會經過 hook，事件裡帶著父會話的 id。所以為主 agent 設的規則，對它啟動的幫手也成立。換成別的平台，我不會在沒測過的情況下假設這點。我沒有測過。

### hook 看不到什麼

這是我最希望你記住的部分。

::: figure 2-2-blind-spot

**它看到的是呼叫，不是效果**。對終端機指令，hook 讀的是指令的文字。它看得到「寫入這個路徑」。它看不到用變數拼出來的路徑，也看不到一分鐘前才寫好、現在才執行的腳本。指令一旦被放行，hook 就不在畫面裡了。所以終端機指令上的 hook，擋得住常見的寫法。它擋不住一個一心要繞過它的 agent。VS Code 文件也這麼說：hook 是可執行的程式碼，不能代替強制的權限或沙箱。對絕不能被碰的東西，不要只靠 hook（[有些東西根本不給](4-5-least-privilege.html)）。

**它不知道是哪個 agent 在呼叫**。在今天的 Copilot 裡，事件不帶主 agent 的名字。所以「這個 agent 被允許」不能成為規則：任何 agent 都可以冒充。如果權限必須不同，就得來自 agent 設不了的東西，例如由人在終端機裡打開的開關。

**它不是到處都會執行**。在我的測量裡，我用 Copilot 的命令列模式（沒有視窗）時，倉庫的 hook 沒有執行。一個看起來像關閉開關的設定，在較新的會話裡也沒能擋住它們。公司的政策可以為一個工作區關掉 hook。而且 hook 檔是在視窗啟動時讀的，所以改了要重新載入。這些是我 2026 年 10 月找到的事實；它們會變。請看平台目前的文件，文件也說 hook 現在是 Preview。

**它可能丟掉自己的訊息**。開頭的故事：hook 的輸出可能永遠到不了模型。要測的是送達，不只是 hook。

### 迴圈裡其他站著的東西

hook 不是模型和外面世界之間唯一的東西。**包裝器**（你呼叫來代替原始指令的小程式）、**MCP server**（[MCP server：插工具的標準接口](1-3-mcp.html)），以及平台和模型之間的**代理**，各自只看得到經過它們的東西，而 agent 可以繞過它們。差別在於：平台保證會呼叫 hook。內建工具和子 agent，我看過每次呼叫都經過它；MCP 工具我沒有測過。

### 測你自己的設定

對你在乎的任何規則，**問三個問題**：

1. 它是寫在 prompt 裡，還是 hook 裡？如果在 prompt 裡，它就是請求。
2. 規則被破壞時，hook 看到什麼？呼叫的文字，還是效果？
3. hook 自己壞掉或很慢的時候，會怎樣？

**今天就能跑的測試**。寫出你的平台允許的最小 hook。它只把事件名稱和工具名稱附加到一個檔案裡。用你的 agent 做一件小任務，然後讀這個檔案。你會依序看到上面表格裡的每個時刻，以及有幾個。這是理解迴圈最快的辦法。檔案格式請照 [VS Code hooks docs](https://code.visualstudio.com/docs/copilot/customization/hooks)。

## 代價和陷阱 {#costs-and-traps}

**逾時是無聲的通過**。上面三種失敗裡，這是對團隊最重要的一種：規則沒有被執行，卻沒有人被告知。要留意你的 hook 花的時間，並在選擇失敗時怎麼辦之前，先讀 [把執行層當軟體來設計](4-4-enforcement-design.html)。

**hook 每次呼叫都會執行**。它慢，一切都慢。我的通常幾十毫秒。要讓它便宜，並限制它能做的事。

**hook 是你必須信任的程式碼**。它在你的機器上執行，讀 agent 送來的任何東西。絕不要在 hook 裡，把 agent 的文字直接放進 shell 指令。在團隊裡，把 hook 檔當成任何其他守著東西的程式碼：改動要經過審查。

**hook 是一個仍在變動的平台的功能**。VS Code 把它標為 Preview。我在失敗表裡寫的是我看到的；每次更新後都再確認一次。

**原因也可能太好**。一個把怎麼繞過規則說得清清楚楚的拒絕，會教模型去那樣做。說該改做什麼，不要說怎麼閃躲。

## 業界怎麼說 {#industry}
{status: industry}

VS Code 列出了我用的那些時刻（會話開始、送出 prompt、工具前後、子 agent 開始和結束、agent 停止），並說明 `preToolUse` hook 可以回傳一個附原因的拒絕。它也指出逾時會落到正常的權限檢查，以及這個功能還在 Preview。（[Agent hooks in VS Code](https://code.visualstudio.com/docs/copilot/customization/hooks)）

我在這裡沒有詳細比較其他平台的 hook。它們的事件名稱和涵蓋的範圍都不同。

## 什麼時候可以刪掉 {#when-to-delete-it}
{status: industry}

只要平台還允許 prompt 裡的規則被忽略，規則用的 hook 就會留著。道理不會退役。我最先會刪的，是各種繞路的做法：平台可靠地送達 hook 的輸出時，防止注入遺失的第二道檢查就可以拿掉；逾時改成會被回報、不再無聲通過時，計時的監看也可以拿掉。如果有一天平台提供原生的、強制執行的政策（一個它自己檢查的規則檔），我會把硬規則搬到那裡，hook 留給紀錄和提醒。
