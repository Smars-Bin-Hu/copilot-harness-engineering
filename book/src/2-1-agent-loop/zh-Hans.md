读这一章，只需要用过写代码的 AI agent，比如 Copilot 的 agent 模式。别的都不需要。

## 一句话 {#in-one-sentence}

agent 是一个循环：问模型，运行它要的工具，把结果喂回去。你在每一轮的几个点上掌舵。

## 写给管理者 {#for-leaders}

- **要拍板的事**：agent 出了问题，先问该改四个地方里的哪一个（它读什么、有哪些工具、调用前的检查、调用后的检查），再去考虑换更大的模型或写更长的 prompt。
- **风险**：循环本身几乎不会坏。按我的观察，错误来自上下文里有什么，或者来自允许它做什么，而写在 prompt 里的规则只是请求。每一种有多常见，我没有统计。
- **做对的代价**：主要是配置的时间。最便宜的杠杆，也就是 agent 读什么，只是几行写下来的规则。
- **可以问团队**：“上一次的坏结果，修的办法是更好的上下文、更紧的工具清单，还是模型之外的一道检查？”

## 问题 {#problem}

agent 做错事的时候，感觉像是一个头脑做了个糟糕的选择。这种感觉会把人引向错误的修法。他们把 prompt 写得更长，或者用大写字母加上一句“小心”，或者换成更大的模型。有时候有用。往往没用，因为问题不出在思考上。

了解这台机器是什么，会有帮助。它又小又朴素。这一章把它画出来，并标出你可以伸手进去的几个地方。这一部分后面的每一章，以及再往后的大多数章，都是在其中某一个地方下功夫。

先说三个词。

- **模型**就是 AI 本身。它读文本、写文本，别的什么都不做。
- **工具**是 agent 在你的项目里能做的一件事：读文件、搜索、改文件、运行命令。
- **工具调用**是模型要求使用某个工具的请求，写成文本：“读这个文件”。

## 原理 {#how-it-works}

### 循环

模型碰不到你的文件。它只能写文本。所以 agent 是这样工作的。模型写出一个工具调用。模型外面的一个程序，也就是不是 AI 的那部分，读到这段文本，真的去运行这个工具。然后程序把结果作为更多文本，贴到模型面前。模型读完，写出下一个工具调用。这样重复，直到模型写出一个不带工具调用的回答。这就是它认为自己做完了的信号。

我把绕这个循环走一圈，叫作一**轮**。有些人用这个词指从你发消息到最终回答的整个来回，而且一圈里模型可以同时要求用好几个工具；这里的一轮，指的是一次“问、运行、喂回去”。

::: figure 2-1-loop

由此得出两个事实，后面都会用到。

1. **每个动作都是一次工具调用**。模型没有别的办法做任何事。所以有一扇门，每个动作都要从这里经过。（对内置工具和子 agent，我见过每次调用都经过 hook 点；MCP 工具我没有测过。细节见 [Hook：每次调用都会经过的执行点](2-2-hooks.html)。）站在这扇门口的人，能看到并拦住 agent 做的一切。hook 就站在那里。它是你的一个小程序，平台在每次工具调用的前后，在固定的点上运行它；[Hook：每次调用都会经过的执行点](2-2-hooks.html)会讲解它。
2. **模型只看得到文本**。它看不到你的屏幕，也看不到你的磁盘。它看到的是上下文里的内容：规则、你说的话、之前工具调用的结果、它自己之前的回答。上下文就是它的整个世界，而且有大小上限。[上下文是一份预算](3-1-context-budget.html)讲的就是这个。

### 它什么时候停？

通常的停止，是模型不再要求工具，直接作答。还有别的情况：你按了停止，平台到了某个上限，或者有什么东西拒绝了这次停止。

最后这一种很有用。agent 要停的时候，可以运行一个 hook，去看任务的待办清单（它还没做完的步骤），然后说“还没完，第 4 步还开着”。循环就接着走下去。这就是让 agent 不用你守着、把一长串清单做完的办法。[慎用子 agent](2-3-subagents.html)讲了这种情况和它的停止规则。Copilot 默认给轮数设了什么上限，我没有查过，所以这里不给数字。

### 你能在哪里插手

再看一遍这个循环。你改变不了模型怎么思考。你能改的，是它周围的四样东西。

1. **它读什么**。放进它上下文的规则和指令，以及指给它的文件。这是用得最多的杠杆，也是最便宜的。[指令与 skill：只加载需要的](3-3-instructions-and-skills.html)讲的是这个。
2. **有哪些工具**。没有改文件工具的 agent，就改不了文件。而且工具的描述和报错信息，是模型拿到的关于它的唯一说明书（[Tool calling，以及怎么给 agent 设计工具](1-2-tool-calling.html)）。自定义 agent 是给一个角色一份更短工具清单的办法（[自定义 agent：固定模型和工具的角色](2-4-custom-agents.html)）。
3. **调用前的 hook**。在调用运行之前就看到它、并且能拒绝它的代码。平台保证每次调用都经过这个点，所以这里的规则是会运行的代码，不是请求。一份工具清单，或者一条让 agent 自查用的命令，也是代码，但各自覆盖的范围更窄（[提示里的规则只是请求](4-1-requests-and-rules.html)）。权限设置和沙箱是另一类杠杆：它们不读调用本身，而是限制任何命令能做什么。我没有在 Copilot 上逐个测过它们，所以没把它们放进这四样里。
4. **调用后的 hook**。看到结果、能留下记录、能为模型加一条备注的代码。它撤销不了已经发生的事。

一个简便的记法：四样里，两样决定模型知道什么，两样决定它被允许做什么。光靠话，只能改变它知道什么。

### 为什么大多数错误不出在循环里

我是这样看 agent 的错误的。循环本身几乎不会坏。错误来自上下文里有什么，或者来自允许它做什么。下面这张清单是我自己用出来的，是我见过的情况，不是统计数据：

| 你看到的 | 通常的原因 |
| --- | --- |
| 它改了不该改的 | 它推理的是怎么把活干完，不是被不被允许。prompt 里的规则只是请求。 |
| 它忘了前面的某件事 | 上下文被压缩了，或者对话太长了。 |
| 它检查了自己的工作，说没问题 | 同一个模型，同样的推理，有同样的盲区。 |
| 它对一个被拒绝的操作不停重试 | 它想把任务做完。 |
| 它说“做完了”，其实没有 | 按我的经验，模型倾向于汇报成功。 |

注意，这几条里很少是因为模型不够聪明。第一条和最后一条，需要模型之外的一道检查。第二条，需要更好的上下文（[长对话会变差](3-2-long-sessions.html)）。第三条，需要另一个视角（[慎用子 agent](2-3-subagents.html)）。只有第四条，接近模型本身的习惯。每一种有多常见，我没有数据，所以这是我对所见的解读，不是测量。

### 自己看看这个循环

你不用安装任何东西。在 agent 的对话里问：“读一下 README，告诉我这个项目是做什么的。”看着对话。回答之前，你会看到一行类似“Read README.md”的字。这一行就是一次工具调用，展示给你看。然后再问一个需要三个文件的问题，数数有几行。每一行是循环的一轮，每个结果现在都在上下文里。

## 代价和坑 {#costs-and-traps}

**每一轮都要重读上下文**。每绕一圈，模型都把整个上下文再读一遍，里面又多了一个结果。一个三十轮的任务，就是对一段越来越长的文本读三十遍。这就是为什么 agent 读什么，比模型多聪明更要紧；也是为什么只看[模型每个 token 的价格](1-1-models-and-cost.html)是不对的。要更正一点：重读并不总是按全价收费。提供方会缓存重复的开头，在 Anthropic 的 API 上，读缓存的价格约是基础输入价的十分之一（算式见[选模型：看每次成功的成本](1-1-models-and-cost.html)）。Copilot 怎么计这笔账，我没有查过。缓存解决不了的是第二笔开销：模型仍然得去关注那一大段文本。

**工具结果是最大的、也是最少被盯着的部分**。prompt 是你写的，所以你知道。agent 读的文件，或者一条命令打印的日志，你可能从没见过。它们仍然在上下文里，模型可能会照着它们去行动。

**agent 不总是答案**。自己决定下一步的循环，比一串固定的模型调用，或者单次调用，更贵，也更难预测。Anthropic 的建议是找最简单的解决办法，只在需要时才增加复杂度（[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)）。如果一件事的步骤从不改变，一个在固定位置调用模型的脚本，可能比 agent 更适合你。

**别把循环当成计划**。模型不会先规划好整条路径再照着走。它每一轮，根据看到的东西来决定。它走上错路，通常是因为前面某一轮的结果把它带过去的。

## 什么时候可以删掉 {#when-to-delete-it}
{status: industry}

只要 agent 还是靠调用工具来工作，关于循环的道理就不会退役。实际操作的那部分也许会。我今天在四个地方掌舵，是因为平台就给了我这些。如果平台开始提供原生的办法来强制执行规则、预算或停止条件，我会用它，而不是我自己的 hook。那时我会丢掉 hook，而不是循环这幅图。

::: prompt
/harness-rookie-wondering 我读完了“agent 循环，以及你能插手的地方”这一章。请教我这个 harness 是怎么站在循环的四个地方的：它往上下文里放了什么、允许哪些工具，以及它的 hook 在调用前后做什么。带我打开真实的文件，并画出一轮是怎么穿过它们的。
