讀這一章，只需要用過 AI 寫程式 agent，例如 Copilot 的 agent 模式。其他都不用。

## 一句話 {#in-one-sentence}

agent 是一個迴圈：問模型，執行它要的工具，把結果餵回去。你可以在每一輪的幾個點上掌舵。

## 給主管 {#for-leaders}

- **要做的決定**：agent 出錯時，先問該修四個地方的哪一個（它讀什麼、有哪些工具、呼叫前的檢查、呼叫後的檢查），再去要更大的模型或更長的 prompt。
- **風險**：迴圈本身幾乎不會壞。依我的觀察，錯誤來自上下文裡有什麼，或者來自允許做什麼，而寫在 prompt 裡的規則只是請求。每一種發生得多頻繁，我沒有計數。
- **做對的成本**：主要是設定的時間。最便宜的槓桿，也就是 agent 讀什麼，只是幾行寫下來的規則。
- **可以問團隊**：「上一次的壞結果，修法是更好的上下文、更緊的工具清單，還是模型外面的一道檢查？」

## 問題 {#problem}

agent 做錯事的時候，感覺像是一個有想法的東西做了壞決定。這種感覺會把人帶去錯的修法。他們寫更長的 prompt，或者用大寫字母加上「小心點」，或者換成更大的模型。有時有用。常常沒用，因為問題不在思考裡。

知道這台機器是什麼，會有幫助。它很小，很普通。這一章把它畫出來，並標出幾個你能伸手進去的地方。這一部分後面的每一章，以及再往後的大部分章節，都在處理其中一個地方。

先講三個詞。

- **模型**就是 AI 本身。它讀文字、寫文字。除此之外什麼都不做。
- **工具**是 agent 在你的專案裡能做的一件事：讀檔案、搜尋、改檔案、執行指令。
- **工具呼叫**是模型要求用一個工具，寫成文字：「讀這個檔案」。

## 原理 {#how-it-works}

### 迴圈

模型碰不到你的檔案。它只能寫文字。所以 agent 是這樣運作的。模型寫出一個工具呼叫。模型周圍有個程式，不是 AI 的那一部分，讀這段文字，真的去執行工具。然後程式把結果當成更多文字，貼回模型面前。模型讀它，再寫出下一個工具呼叫。這樣重複，直到模型寫出一個不含工具呼叫的回答。這就是它認為自己做完了的訊號。

我把繞這個迴圈一圈叫做**一輪**。有些人用這個詞指從你的訊息到最後回答的整段來回，而且模型一圈可以同時要求好幾個工具；這裡的一輪，是問、執行、餵回去這一個回合。

::: figure 2-1-loop

由此得到兩個事實，之後都很重要。

1. **每個動作都是工具呼叫**。模型沒有別的辦法做任何事。所以有一扇每個動作都經過的門。（內建工具和子 agent，我看過每次呼叫都經過 hook 的位置；MCP 工具我沒有測過。細節見 [Hooks：每次呼叫都會經過的執行點](2-2-hooks.html)。）站在這扇門口的人，看得到、也擋得住 agent 做的一切。hook 就站在那裡。它是你的一個小程式，平台在每次工具呼叫之前和之後的固定位置執行它；[Hooks：每次呼叫都會經過的執行點](2-2-hooks.html) 有說明。
2. **模型只看得到文字**。它看不到你的螢幕，也看不到你的磁碟。它看到的是它的上下文裡有的：規則、你說的話、之前工具呼叫的結果、它自己之前的回答。上下文就是它的整個世界，而且有大小上限。[上下文是一份預算](3-1-context-budget.html) 講的就是這個。

### 什麼時候停？

一般的停止，是模型沒有要求工具就直接回答。還有別的：你按了停止、平台到了上限，或者有東西拒絕了這次停止。

最後這個很有用。agent 要停下來的時候，hook 可以執行，看任務的待辦清單（它還開著的步驟），然後說「還沒，第 4 步還沒做完」。迴圈就繼續。這就是讓 agent 不靠你、把一長串清單做完的辦法。[慎用子 agent](2-3-subagents.html) 講了這種情況和它的停止規則。Copilot 預設把輪數限制在多少，我沒有查過，所以這裡不給數字。

### 你能在哪裡插手

再看一次迴圈。你改變不了模型怎麼思考。你可以改變它周圍的四樣東西。

1. **它讀什麼**。放進它上下文的規則和指令，以及指給它看的檔案。這是用得最多、也最便宜的槓桿。[指令與 skill：只載入需要的](3-3-instructions-and-skills.html) 講的就是這個。
2. **有哪些工具**。沒有改檔案工具的 agent，就改不了檔案。而且工具的描述和錯誤訊息，是模型拿到的唯一手冊（[Tool calling，和給 agent 設計工具](1-2-tool-calling.html)）。custom agent 是給一個角色較短工具清單的辦法（[Custom agent：固定模型和工具的角色](2-4-custom-agents.html)）。
3. **呼叫前的 hook**。在呼叫執行前看到它、並且能拒絕它的程式碼。平台保證每次呼叫都會經過這一點，所以這裡的規則是會執行的程式碼，不是請求。工具清單，或 agent 用來檢查自己的指令，也都是程式碼，但各自涵蓋的範圍窄一些（[提示裡的規則只是請求](4-1-requests-and-rules.html)）。權限設定和沙箱是另一種槓桿：它們不讀呼叫，而是限制任何指令能做什麼。我沒有在 Copilot 上一項項測過，所以把它們放在這四個之外。
4. **呼叫後的 hook**。看到結果、可以留下紀錄、並且能為模型加一則備註的程式碼。它沒辦法撤銷已經發生的事。

一個簡單的記法：四個裡有兩個決定模型知道什麼，兩個決定它被允許做什麼。文字只改變它知道什麼。

### 為什麼大部分錯誤不在迴圈裡

我是這樣看 agent 的錯誤的。迴圈本身幾乎不會壞。錯誤來自上下文裡有什麼，或者來自允許做什麼。這是我根據自己的使用留下的清單。這是我看到的，不是統計：

| 你看到的 | 通常為什麼 |
| --- | --- |
| 它改了不該改的 | 它推理的是怎麼把事做完，不是被不被允許。prompt 裡的規則只是請求。 |
| 它忘了先前的某件事 | 上下文被壓縮了，或者對話太長。 |
| 它檢查了自己的工作，說沒問題 | 同一個模型、同樣的推理，有同樣的盲點。 |
| 它一直重試被拒絕的動作 | 它想把任務完成。 |
| 它說「做完了」，其實沒有 | 依我的經驗，模型傾向回報成功。 |

注意，這些裡面很少是模型不夠聰明。第一個和最後一個，需要模型外面的一道檢查。第二個需要更好的上下文（[長對話會變差](3-2-long-sessions.html)）。第三個需要第二個視角（[慎用子 agent](2-3-subagents.html)）。只有第四個接近模型自己的習慣。每一種發生得多頻繁，我沒有計數，所以這是我對所見的看法，不是量出來的。

### 自己看看迴圈

你不用安裝任何東西。在 agent 的對話裡問：「讀 README，告訴我這個專案做什麼。」看著對話。回答之前，你會看到一行像「Read README.md」的字。那一行就是一次工具呼叫，秀給你看的。然後問一個需要三個檔案的問題，數一數有幾行。每一行是迴圈的一輪，每個結果現在都在上下文裡了。

## 代價和陷阱 {#costs-and-traps}

**每一輪都要重讀上下文**。每繞一圈，模型都要把整個上下文再讀一遍，現在多了一個結果。三十輪的任務，就是三十次讀一份越來越長的文字。這就是為什麼 agent 讀什麼，比模型有多聰明更重要，也是為什麼只看[每個 token 的單價](1-1-models-and-cost.html)，是看錯了數字。要更正一點：重讀不一定按全價收費。供應商會把重複的開頭快取起來，在 Anthropic 的 API 上，讀快取的價格大約是基本輸入價的十分之一（[選模型：算的是每次成功的成本](1-1-models-and-cost.html) 有算式）。Copilot 怎麼計費，我沒有查過。快取解決不了的是第二種成本：模型還是得去注意那麼多文字。

**工具結果是最大、也最少人看的部分**。prompt 是你寫的，所以你知道。agent 讀的檔案，或指令印出的紀錄，你可能從來沒看過。它還是在上下文裡，而模型可能照著做。

**agent 不一定是答案**。自己決定下一步的迴圈，比一串固定的模型呼叫，或單次呼叫，花得更多，也更難預測。Anthropic 的建議是找到最簡單的解法，只在需要時才加複雜度（[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)）。如果一件工作的步驟從來不變，一個在固定位置呼叫模型的腳本，可能比 agent 更適合你。

**別把迴圈當成計劃來讀**。模型不是先規劃好整條路再照著走。它每一輪都根據看到的東西決定。它走上錯的路，通常是因為前面某一輪的結果把它帶去的。

## 什麼時候可以刪掉 {#when-to-delete-it}
{status: industry}

只要 agent 還是靠呼叫工具運作，關於迴圈的推理就不會退役。實務的部分可能會。今天我在四個地方掌舵，是因為平台給我的就是這些。如果平台開始提供原生的辦法，來執行規則、預算或停止條件，我會用那個，不用自己的 hook。那時我會丟掉 hook，不會丟掉迴圈的圖像。

::: prompt
讀這個專案的指令檔和設定。你找到的每條規則或限制，都告訴我它作用在四個地方的哪一個：agent 讀什麼、有哪些工具、工具呼叫前的檢查，或工具呼叫後的檢查。把每一條只是寫下來的請求、模型外面沒有任何東西執行它的規則標出來。列出五條壞掉時影響最大的規則。不要改任何檔案。

## 在 harness 裡探索 {#explore}

迴圈到處都一樣，但在 harness 裡，你可以從旁邊看每一輪：什麼被注入了上下文，hook 看到了哪次呼叫、答了什麼。照上面的說明準備好之後，輸入：

::: prompt
/harness-rookie-wondering 我讀完了「agent 循環，和你能插手的地方」這一章。請教我這個 harness 怎麼站在迴圈的四個位置：它把什麼放進上下文、允許哪些工具，以及它的 hook 在呼叫之前和之後做什麼。帶我打開真實的檔案，並畫出一輪怎麼經過它們。
:::

它一次教一小塊，停下來確認你跟得上，然後和你一起打開檔案。
