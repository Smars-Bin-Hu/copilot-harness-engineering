讀這一章，請先用過 AI 寫程式的 agent，並讀過[上下文是一份預算](3-1-context-budget.html)（agent 讀的所有東西共用一個大小有限的視窗）。

## 一句話 {#in-one-sentence}

預設只載入最少的規則，其餘的在需要時才讀。skill 是一本按需要才讀的手冊，而且和任何寫下來的規則一樣，不會被強制執行。

## 給主管 {#for-leaders}

- **要做的決定**：讓一直載入的規則保持很少，並決定誰負責規則檔、誰去剪掉不再需要的。
- **風險**：長的規則檔比短的更不容易被遵守，兩個互相矛盾的檔案會讓模型挑一個。寫在檔案裡的規則仍然只是請求：模型可以不照做。一定要成立的東西，要放進程式碼。我手上沒有可以引用的、規則被無視的實測案例。
- **做對的成本**：一個負責人，和定期修剪規則檔。剪掉 agent 本來就會做對的行，成本很低；在我自己的檔案裡，我通常沒看到有什麼變差，但我沒有系統地測過。
- **可以問團隊**：「我們一直載入的檔案裡，哪幾行是 agent 沒有它們就會做錯的？誰負責那個檔案？」

## 問題 {#problem}

教 agent 認識你的專案，最自然的辦法是把一切都寫進一個檔案：規則、慣例、警告、每份工作的做法。agent 每犯一次錯，你就加一行。幾個星期後，檔案很長，agent 遵守它的程度比它還短的時候差。

有兩件事出了問題。它們是這一章的主題。

- **每一輪都要為所有東西付錢**。這個檔案一直在視窗裡，不管這份工作需不需要。你在改一個錯字，資料庫遷移的規則卻佔著位子。這個位子就是[上下文是一份預算](3-1-context-budget.html)講的那份預算；每一輪要花多少，在[選模型：算的是每次成功的成本](1-1-models-and-cost.html)。
- **規則越多，每一條被遵守的程度越低**。長的檔案讓規則互相競爭。兩行可能互相矛盾；要緊的一行淹沒在小的之間。Claude Code 和 VS Code 的文件都建議讓指令檔保持簡短，Claude Code 的還警告，兩條指令互相矛盾時，模型可能隨意挑一條。

先說三個詞。

- **指令**是寫給 agent 讀的規則檔。有些在每個對話裡都載入。其他的只在 agent 處理特定檔案時才載入。
- **skill** 是一個資料夾，裡面是某一類工作的手冊。agent 在這份工作出現時才讀手冊，不是事先讀。
- **漸進式揭露**（progressive disclosure）是兩者背後的想法：先給 agent 看一點，需要更多時才讓它多讀。就像一家店，門口有菜單，完整的食譜在廚房裡。Anthropic 稱它是「讓 Agent Skills 靈活、可擴展的核心設計原則」（[Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)）。

我手上沒有可以引用的、規則被無視的實測案例，所以這一章給的是推理和檢查的辦法。

## 原理 {#how-it-works}

### 1. 規則的三個位置

規則放在哪裡，決定它什麼時候佔位子、agent 什麼時候看得到。

::: figure 3-3-places

- **一直載入**。倉庫根目錄裡一個簡短的檔案，每個對話都讀。只有每份工作都需要的規則放在這裡：安全限制、怎麼開始、被拒絕時該怎麼辦。在我的設定裡，它只有短短一頁。如果一條規則十份工作裡只有一份需要，它就不屬於這裡。
- **依檔案載入**。只適用於某一類檔案的規則。在 VS Code 裡，指令檔有一行檔頭 `applyTo`，內容是像「這個資料夾底下所有檔案」這樣的模式。只有 agent 打開符合的檔案時，規則才載入。寫 skill 的規則，在它打開 skill 檔案時載入，編輯 pipeline 時不佔任何位子。下面是這樣一個檔案的開頭：

::: code harness .github/instructions/skills.instructions.md L1-L4 "只在處理 skill 檔案時載入的指令檔：applyTo 那一行就是模式。"
- **按需要才讀**。其他一切：很長的做法說明、很少用到的細節。skill 和參考筆記放在這裡。工作需要時，agent 才去讀。

第四種方式：**hook**（平台在固定時刻執行的小程式；見 [Hooks：每次呼叫都會經過的執行點](2-2-hooks.html)）可以在你送出的每則訊息最前面加上幾行，在用到的地方重複一條規則。只放幾行，不然你又重建了那個長檔案。

對每一條規則的問題是：**這條多常需要？agent 漏掉了會怎樣**？每次都需要、漏掉代價高：一直載入。只有某一類檔案需要：依檔案載入。只有某一份工作需要：skill。

### 2. skill 分三層載入

skill 是一個資料夾。主檔案 `SKILL.md` 有一段檔頭（名稱和描述）和一段正文（手冊）。旁邊可以放更長的筆記、腳本和範本。

::: figure 3-3-three-layers

agent 不會一次看到全部。

1. **一直都在的，是每個 skill 的名稱和描述**。這是菜單。它很小，但你裝了多少個 skill，每一輪就要為它們付多少錢。
2. **請求符合某個描述時，載入整本手冊**。這是 agent 自己決定的，或者你輸入 skill 的名稱。
3. **只有手冊指向時，才載入額外的檔案**。很長的參考資料或腳本，在需要它的那一步才讀。

所以你可以裝很多 skill，而不會塞滿視窗。

**描述決定 skill 到底找不找得到**。在第 1 層，描述是 agent 手上全部的東西。含糊的描述（「幫助提升程式碼品質」）永遠對不上任何東西。好的描述說三件事：這個 skill 做什麼、什麼時候用（「use when……」），以及人真的需要它時會說的那些字。平台對長度有限制，而囉嗦的描述也會佔掉其他每個 skill 的位子。

就算描述很好，也不保證會用。VS Code 的文件明確說，發現機制讓 skill 可以被用到，但不保證模型會用某一個。所以要測（見下面）。

**菜單也可能太長**。有幾十個 skill 時，菜單是一筆實實在在的成本，而且很多從不會被選到。一個辦法是，把單一業務領域的 skill 擋在菜單之外，直到任務和這個領域有關。

### 3. 一條規則，一個來源

同一條規則如果寫在三個檔案裡，改的時候會漏掉其中一個，agent 讀到三個慢慢分歧的版本。規則只寫在一個地方。其他地方放一個連結和一句話。一條規則如果得到處重述，說明結構錯了。規則檔是共用的程式碼，所以要給它們一個負責人，由他剪掉不再需要的行。

### 4. 寫下來的規則為什麼會被無視

規則載入了，仍然可能沒被遵守。常見的原因：

1. **檔案太長**。對每一行問：沒有它，agent 會做錯嗎？不會，就刪掉這一行。
2. **規則互相衝突**。兩個檔案說的不同。模型挑一個，而且不一定是你要的那個。VS Code 的文件說，指令的來源是疊加的，不要靠檔案的順序來解決衝突。所以消除衝突是你的工作：去搜尋，並修改措辭，只留下一個版本。
3. **規則離適用的地方很遠**。它在第一則訊息裡，現在在幾千行之上。依檔案載入的規則或 hook 的提醒，可以把它放得近一點。
4. **它沒有理由**。「絕對不要做 X」很容易被繞過去。「絕對不要做 X，因為 Y 會壞掉」，讓模型能把這個想法用在你沒列出來的情況上。
5. **它只是請求**。這是最根本的原因。你寫在檔案裡的任何東西，都是模型去讀的，而模型可以不照做。Claude Code 的文件說得很直白：memory 檔是「上下文，不是強制執行的設定」，不管模型怎麼決定，想擋掉某個動作，就用 hook。skill 的文字也一樣。它讓工作進行得順利；它不讓錯的事不可能發生。在某些平台上，skill 的檔頭可以帶更強的設定，你應該去查它們做什麼。例如在 Claude Code 裡，`allowed-tools` 只是預先批准工具，並不限制工具，而且 skill 可以註冊 hook，那是程式碼（[Skills](https://code.claude.com/docs/en/skills)）。

對第五點，補救不是更好的措辭。一條必須成立的規則要放進程式碼。這個選擇是[提示裡的規則只是請求](4-1-requests-and-rules.html)的主題。這時文字只需要解釋為什麼，免得 agent 再試著繞過那個拒絕。在我的設定裡，要緊的規則有兩層：文字負責教，程式碼負責擋。

### 5. 還有一個選擇：語言

如果你用不止一種語言工作，我只留一份規則和 skill，用英文寫，再告訴模型用哪種語言回答。第二份散文，會慢慢和第一份漂開。這是我的選擇；原則只是只有一份。

### 測一測你自己的設定

**你加的每一條規則，都問這三個問題**：

1. 這條多常需要？很少的話，就不放進一直載入的檔案。
2. 別處已經寫過了嗎？有的話，連過去。
3. agent 無視它會怎樣？答案如果是「很糟、而且無法挽回的事」，那就不是文字能做的事。

**今天就能做、不用額外設定的測試**。看你一直載入的檔案。每一行都問：沒有它，agent 會做錯嗎？把不通過的行都剪掉。然後跑和之前一樣的任務，看有沒有什麼變差。我從自己的規則檔剪掉一些行時，通常沒看到什麼變差。我沒有系統地測過。

**測 skill 找不找得到**。先把請求寫好，用人會說的字，不是描述裡的字：三種要求這份工作的說法，和兩個相鄰、不該觸發它的請求。每一個都開一個新的對話（舊的對話可能已經載入了這個 skill），而且不要輸入 skill 的名稱。然後看哪些 skill 被載入了。平台有紀錄的話就用紀錄，因為 agent 自己說的不算證據。沒載入，說明描述缺少使用者的字。不該載入時載入了，說明描述太寬。

**測 skill 有沒有改變什麼**。同一個任務在新的對話裡跑兩次，有 skill 和沒有 skill 各一次。看不出差別的話，就剪掉那些沒有差別的行。agent 本來就知道它們。

## 代價和陷阱 {#costs-and-traps}

**拆開是有代價的**。skill 裡的規則，只有 skill 被找到時才會被讀。一條要緊的規則，放在描述很弱的 skill 裡，可能永遠不會被讀。這是省位子的代價。漏掉的代價高的話，就把它留在會載入的地方。

**skill 不是設定**。它靠模型去選它。同一個請求，這次可能載入它，下次就不載入。

**skill 越多，越難選**。就算是好的描述，也可能和它的鄰居混淆。每一個都保持狹窄，並寫明它不是做什麼的。

**注入文字的 hook 會累加**。每一行都會在每則訊息裡重複。Claude Code 的文件建議專案檔低於約 200 行；那是經驗法則，不是量出來的限制。量你自己的。

## 業界怎麼說 {#industry}
{status: industry}

- **VS Code** 對 skill 也有三層載入：先讀名稱和描述，「skill 相關時」才載入正文，其他檔案「只有在被引用時」才讀。它還說，發現機制「不保證每個相關的 prompt 都會呼叫某個 skill」。對於指令檔，它建議「讓你的指令簡短而獨立」「附上規則背後的理由」，並說來源是「疊加的」。（[Agent skills](https://code.visualstudio.com/docs/copilot/customization/agent-skills)、[Custom instructions](https://code.visualstudio.com/docs/copilot/customization/custom-instructions)）
- **Anthropic** 為 Agent Skills 描述了同樣的三層：先是名稱和描述，skill 適用時載入正文，連結的檔案只在需要時才載入。（[Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)）
- **Claude Code** 建議每個 memory 檔保持在 200 行以下，把屬於程式碼某一部分的規則移到只在路徑符合時才載入的檔案，並移除矛盾。它把這些當成「上下文，不是強制執行的設定」。（[How Claude remembers your project](https://code.claude.com/docs/en/memory)）

兩個平台用的是同一個形狀：一直開著的檔案、依路徑載入的規則、按需要才讀的 skill。想法在各個工具之間是一樣的，所以你在這裡做的東西可以帶著走。

## 什麼時候可以刪掉 {#when-to-delete-it}
{status: industry}

平台可能接手的手動部分：只列出目前領域的 skill，以及剪短過長的菜單。如果平台學會更好地按相關性載入 skill，領域這個辦法就可以不用了。

道理不會退役。更大的視窗不會讓長的規則檔變好；它只是讓你在問題出現之前能放更多。而且沒有任何載入方式，能讓寫下來的規則變成強制執行。如果有平台能在我自己的任務上證明，長的規則檔被遵守的程度和短的一樣好，我會再看一次。

## 在你自己的環境試試 {#try-it}

不用裝 harness。在你自己的倉庫裡打開 agent，貼上：

::: prompt
審查這個倉庫裡的指令檔和 skill。列出：一直載入的檔案裡，不用說你也會做對的行；寫在不止一個地方的規則；互相矛盾的規則對；沒有給理由的規則；以及描述太含糊、找不到，或太寬的 skill，並為每一個給出更好的描述。標出犯錯會代價高昂又無法挽回的規則，那些需要程式碼，不是文字。不要改任何檔案。

## 在 harness 裡探索 {#explore}

Copilot Harness 用到了全部三個位置、三層載入，以及一條規則只有一個來源的做法。harness 可以用真實的檔案讓你看到每一樣。照上面的說明準備好之後，輸入：

::: prompt
/harness-rookie-wondering 我讀完了「指令與 skill：只載入需要的」這一章。請教我這個 harness 怎麼用規則的三個位置、它的 skill 怎麼分三層載入，以及為什麼說 skill 不是強制執行的（主題 2、3 和 15）。帶我打開真實的檔案，從最短的那個開始。
:::

它一次教一小塊，並和你一起打開檔案。
