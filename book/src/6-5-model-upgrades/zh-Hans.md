读这一章，你需要用过一个写代码的 AI agent，并且给它写过规则或步骤。别的都不需要。

## 一句话 {#in-one-sentence}

模型升级了，先重跑你的评测。然后把新模型已经不需要的规则、检查和步骤删掉，因为为旧模型搭的脚手架，可能会拖慢新模型。

## 写给管理者 {#for-leaders}

- **要拍板的事**：每次换模型之后，安排一次对配置的复查，并定下谁来重跑评测、谁有权删规则。
- **风险**：为旧模型搭的规则和步骤，可能会拖慢新模型。我没有在一次升级上测过这一点；这是担心，不是结果。防止破坏的硬性限制、记录和评测，不在要砍的清单上。
- **做对的代价**：把你的固定任务重跑，不止一遍，再加一个人的时间，一次删一块。主要是钱和时间；我没有数字。
- **可以问团队**：“如果明天换了模型，我们会先试着删掉哪些规则？哪些评测能告诉我们结果？”

## 问题 {#problem}

把 agent 周围的配置，想成**脚手架**，也就是工人盖楼时在楼外搭起来的架子。里面的每条规则、每项检查、每一步写明的步骤，当初放进去都有理由。每一个，都是在补当时那个模型做错的、做得差的或忘掉的东西。

然后模型升级了。那些理由说的是旧模型。其中一些已经不成立了。没人通知你的配置。

这是个实实在在的担心，虽然我没有在一次升级上测过。我自己的 harness 的第一版，有分级，还有三个按岗位分工的 agent。用了几天后，那三个 agent 被拿掉了，依据是[慎用子 agent](2-3-subagents.html)里的证据，那一章有成本数字和它们的局限。分级被拿掉，则是另一个原因（[我砍掉了什么，数据怎么说](7-3-what-we-cut.html)）。两样东西在当时都显得合理。我从中得到的是一个问题，不是一个结果：模型还弱的时候搭起来的结构，在模型变强之后，可能不再值它的成本，而且在有人去测它、去掉它之前，它会一直花钱。本章其余部分，讲的就是怎么测。

没用的脚手架，在三个方面花钱。

- **时间和钱**。每多一步，每个任务都要为它付一次。
- **空间**。一份很长的规则文件，每一轮都占着上下文窗口的一部分（[上下文是一份预算](3-1-context-budget.html)）。
- **混乱**。为旧模型的某个习惯写的规则，可能把新模型往错的方向拉。这种情况多常发生，我没测过。这是风险，不是测出来的效果。

## 原理 {#how-it-works}

规则很简单：**不凭感觉删，也不凭习惯留。跑评测**。图里画出了顺序。

::: figure 6-5-thinner

### 1. 升级之前，先准备好能重跑的东西

这就是[固定任务](6-3-eval-tasks.html)排在前面的原因。如果你没有一组固定任务，也没有给它们打分的脚本，那么升级就是一个你没法评判的改动。把这组任务和它以前的结果留着。它们是基线。

### 2. 只换模型，重跑

在新模型上，用同样的配置跑同样的任务。和基线比较。确认只有模型变了：新模型对文本的分词方式可能不同，默认的思考量可能变，一开始还可能没命中 prompt 缓存，这些都会改变成本，却不改变质量。把它们和数字记在一起。如果提供方发布了从旧模型迁移到新模型的说明，重跑之前先读，这样你就知道该留意什么。会出现两种情况。

- **某个地方变差了**。旧模型下管用的规则，换了新模型可能就不管用了。先知道这一点更好。模型升级和其他改动一样，也可能把东西弄坏。
- **变好了，或者一样**。那么要看的差距就是成本：时间、用量、轮数。

因为每次运行都不一样（[一次运行证明不了什么](6-4-variance.html)），每个都要跑不止一次，否则你会把噪声当成结果。

### 3. 不管评测怎么说，都不能删的

有些东西，根本不该上清单，开始删之前先清楚这一点更好。

- **防止破坏的硬性限制**。拒绝碰生产环境、守护规则文件、不可撤销的事要由人审批。这些不取决于模型有多聪明；它们防的是模型出错或被骗时会发生什么。**模型变好了，不是去掉它们的理由**（[有些东西根本不给](4-5-least-privilege.html)）。
- **记录**。更好的模型也需要日志、报告，以及读它们的人（[记下发生了什么](6-1-observe.html)）。
- **评测**。其他一切，都靠它来决定。

各层变化的速度不一样。文本（规则和步骤）变得最快，也最容易砍。用代码做的强制执行变得慢一些，而且要靠评测来定。平台的变化在这一切的底下。

### 4. 一次只拿掉一块

现在对每一块脚手架问：新模型还需要它吗？要知道答案，就拿掉它，再把任务重跑一遍。一轮只动一块，否则你不知道是哪一块起了作用。

对独立检查这类东西，实验是直接的。开着检查和关掉检查各跑一遍任务，然后比较。如果评测显示没有差别，这项检查在这些任务上就不值它的成本（[慎用子 agent](2-3-subagents.html)对第二个 agent 也是同样的道理）。如果它仍然能抓出问题，就留着。

### 5. 我会先看什么

这几块，是我预期在自己配置里最先被考虑的候选。我把它们列成要测的东西，不是结果；模型升级之后，我还没有重跑过它们。

| 部分 | 为什么可能变 | 我会怎么做 |
| --- | --- | --- |
| 针对各类工作写明的步骤手册 | 更新的模型可能不需要把步骤写得那么细 | 把它们缩短。保留“什么算做完”的清单：它们说的是你要什么，不是怎么得到（[管任务，不管对话](5-1-tasks.html)） |
| 独立检查 | 模型可能更可靠地检查自己 | 比较不检查和检查一次。只有当评测显示两者没有差别，默认才变成不检查 |
| 提醒和变通办法 | 它们补的是旧模型的某个习惯 | 关掉它们再测（[把团队的做法写成 skill](3-4-skills-and-workflows.html)对“坑”也是这么说的） |
| 因为模型不听而挪进代码的规则 | 新模型可能会遵守 | 在违反了也能撤销的地方，把代码里的规则关掉，并计数（[提示里的规则只是请求](4-1-requests-and-rules.html)） |
| 每个角色用哪个模型 | 新模型会不断出来 | 只改这一项设置，再跑任务 |
| 为旧模型调过的措辞 | 为了让某个模型听见而写的强调，对另一个模型可能太重 | 用平实的话重写，再跑任务。我没有测过这一点 |

本书几乎每一章的结尾，都有一节叫“什么时候可以删掉”。这一节就是这一步要用的清单。升级之后，我按顺序过一遍这些节，对每一节问它的条件现在成不成立。

### 6. 写下你删了什么，什么时候会放回去

我拿掉一样东西时，会写一行：什么、为什么，以及什么证据会让它回来。这能防止配置变成瞎猜。下一个模型在某件事上更差时，你就知道该看哪一行。（同样的习惯贯穿[我砍掉了什么，数据怎么说](7-3-what-we-cut.html)。）

### 测你自己的配置

**三个问题**：

1. 如果明天模型升级了，你会重跑什么，来看你的配置还管不管用？
2. 哪条规则或哪一步，你留着只是因为曾经加过？
3. 哪一个删了会出问题？你怎么知道？

**今天就能做的一个测试**。挑你配置里一条你怀疑是累赘的规则或步骤。选三个它应该起作用的任务。先把规则文件复制一份，这样你能把规则放回去。有它和没它各跑一遍任务，不止一次，比较通过情况和用量。如果你分不出两者的差别，你就学到了东西。如果它确实有影响，你就知道了这条规则值多少。

## 代价和坑 {#costs-and-traps}

**拿掉东西也是一种改动，也可能把东西弄坏**。一次只拿掉一块，每拿掉一块就跑一次评测。

**评测就是边界**。你只能说某一块对你测过的那些任务不需要。如果任务很少，就这么说，并且对任何防止破坏的东西要格外小心。

**重跑要花钱**。每次发布新模型都完整重跑一遍，不一定负担得起。换了模型系列、版本号变了，或者你注意到行为变了，就重跑。缓存在这里有影响：在 Anthropic 的 API 上，命中缓存的读取约是基础输入价格的十分之一（[选模型：看每次成功的成本](1-1-models-and-cost.html)），但新模型上最初几次运行是冷启动，我也没有查过 Copilot 对这些怎么计费。

**新模型可能在某件事上更差**。升级不一定在每个任务上都更好。评测也是为这个准备的。

**脚手架可能掩盖弱点**。一项总能抓住同一个错误的检查，可能正是让你没注意到这个错误的东西。拿掉它的时候，去看失败的运行。

## 什么时候可以删掉 {#when-to-delete-it}
{status: industry}

这一章本身就是一套删东西的流程，那还有什么可删的？就是一步一步重跑的那套做法。如果平台能在你自己的任务上告诉你一次升级改变了什么，或者每次发布都替你跑评测，我会用它。习惯留下来：配置里没有什么是永久的，每一块都得对照你现在用的这个模型，证明自己该留下。

## 在 harness 里探索 {#explore}

Copilot Harness 有一份清单，列着它预期在模型升级后最先会变的东西，还有一份清单，列着它选择不做的东西，以及什么时候会重新考虑。harness 能带你把这两份都过一遍。完成上面的配置后，输入：

::: prompt
/harness-rookie-wondering 我读过“模型升级了，就要删”这一章。请教我这个 harness 预期在模型升级后哪些东西会变（主题 15），以及它永远不会删什么。对每一部分，和我一起打开真实的文件，给我看怎么测试它是否还需要。
:::

它一次只教一小块，会停下来问你跟不跟得上，并和你一起打开文件。
