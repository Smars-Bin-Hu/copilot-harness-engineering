這一章假設你讀過[提示裡的規則只是請求](4-1-requests-and-rules.html)：一定要守住的規則，必須是程式碼，不能只是文字。

## 一句話 {#in-one-sentence}

「先問我」不是限制，因為問到第一百次，人就會直接點允許。限制是 agent 吵不贏的拒絕，並且按動作可能弄壞多少來分級。

## 給主管 {#for-leaders}

- **要做的決定**：決定「先問我」不算安全限制。一定不能發生的動作，要用拒絕，並按出錯的代價分級。問人，留給少見的、需要判斷的情況。
- **風險**：問到第一百次，人就直接點允許；平台還提供把詢問框整個拿掉的辦法。VS Code 說，全域自動批准會「繞過所有使用者批准，可能導致破壞性的動作」。我沒有量過人有多常不看就點。
- **做對的成本**：一小組拒絕規則，每條都附一句 agent 能照著做的原因，再加一個人去看日誌，找觸發太頻繁的規則。把 agent 關進沙箱，可以減少詢問框的數量：Anthropic 說它自己內部使用時，權限提示少了 84%，這是它對自己工具的數字。
- **可以問團隊**：「我們的 agent 有哪些動作，不用任何人在場就能做？其中有沒有無法撤銷的？」

## 問題 {#problem}

讓 agent 保持安全，最直覺的辦法是讓它先問。執行指令之前彈出一個框：允許或拒絕。你說了算，沒有你點頭什麼都不會發生。

第一天這招有用。第一個指令，你會讀。第十個，你掃一眼。到第一百個，框還沒畫完你就點了允許，因為前面九十九個都沒事。這不是偷懶。幾乎每個問題的正確答案都一樣時，人就是這樣。框已經變成一段延遲，不再是檢查。（這是我和很多人看到的，也是平台文件提醒過的。我沒有量過有多頻繁，見結尾。）

然後平台給你幾種辦法去掉這段延遲，你也會用，因為延遲很煩：

- **全部允許**。一個設定，詢問框再也不出現，動作直接執行。
- **這個會話內允許**。在一個框上點一下，同一類動作在這次對話裡就不再問。
- **Autopilot**。agent 在沒人守著鍵盤時繼續工作。框也許會彈出來，但沒人看。

VS Code 說得很直接：全域自動批准會「繞過所有使用者批准，可能導致破壞性的動作」，它對指令的解析也只是「盡力而為」（[security](https://code.visualstudio.com/docs/copilot/security)）。它的 hooks 頁面還補了一句：`ask`「需要互動式的批准流程」，所以別以為它能讓無人值守的會話停下來（[hooks](https://code.visualstudio.com/docs/copilot/customization/hooks)）。

我試了三種模式（預設、全部允許、Autopilot），有一樣東西都守住了：hook 發出的**拒絕**。詢問框可以被關掉。拒絕不能在彈窗裡被點掉。（人仍然可以改規則本身，[保護規則本身的檔案](4-3-guardrails.html)講的就是怎麼安全地改。）

## 原理 {#how-it-works}

### 詢問和拒絕

先說清楚兩個詞。**詢問**是停下來，等人說好。**拒絕**是不等人就說不，而且每次都用同樣的方式說。agent 能說服人答應（人也能自己說服自己）。但只要程式還在跑，agent 就說服不了程式收回一個不。

::: figure 4-2-ask-vs-refuse

所以兩者各管不同的事。

- **拒絕**不能發生的事。你永遠不會批准的，或者無法撤銷的。不該讓人對這些事說一百次不；程式說一次，並且永遠這樣說。
- **詢問**要靠人判斷的事，而且這種事很少。詢問框只有少到會被人讀的時候才管用。把它用在值得人花注意力的地方。

一個重要的詢問還需要一樣東西：它必須經過 agent 自己按不到的管道傳到人那裡。對話裡的框，可以被「這個會話內允許」關掉。我會在[兩道門：人在哪裡批准](5-3-two-approvals.html)再講這一點。

### 終端機最難管

編輯工具很好管。路徑是呼叫裡的一個欄位，規則就是「拒絕這個路徑」。

終端機不行。它是 agent 最強的工具，因為你能執行的它都能執行。它也最難管，因為同一個效果有很多種寫法：重新導向、`rm`、`sed -i`、執行另一個腳本的腳本。hook 讀的是指令的文字。常見的寫法它攔得住，但攔不住用變數拼出來的路徑，也攔不住先寫好再執行的腳本（[Hooks：每次呼叫都會經過的執行點](2-2-hooks.html)）。所以終端機上的規則永遠不會「完整」。這不是不寫的理由，而是要老實說它們是什麼：防的是失誤，不是一個鐵了心繞過去的 agent。

### 按後果分級

攔不住所有的事，就按出錯的代價來攔。不要按任務難不難來分。難的任務可能無害，簡單的指令也可能毀掉一整天。程式可以從路徑和指令判斷後果，所以你不必替每個任務手動選等級。注意它的限制：程式看到的是指令的文字，不是它的效果。這個等級是從文字猜出來的（見下面的陷阱）。

::: figure 4-2-grades

| 後果 | 例子 | 我怎麼做 |
| --- | --- | --- |
| 只讀 | 查東西、讀檔案 | 不攔 |
| 可以撤銷的寫入 | 在工作資料夾裡編輯、寫計劃 | 允許，只限在劃定的範圍內 |
| 寫進真正的倉庫 | 別人會用到的程式碼 | agent 先寫在工作區。寫回去之前由人批准（[兩道門：人在哪裡批准](5-3-two-approvals.html)） |
| 無法撤銷 | push、刪分支、reset --hard | 拒絕。agent 永遠得不到答應。由人自己做 |

規律是：出錯的代價越大，agent 能自己決定的就越少。到最上面一級，就完全不問了。

### 以 git 為例

git 兩端都有，所以是個好例子。在我的設定裡，連上倉庫後：

- **讀的放行**。`status`、`diff`、`log` 這類永遠不攔。
- **寫的會被拒絕，但附一條出路**。`add`、`commit`、切換分支。拒絕訊息裡有完整的指令和一個代碼。人讀完，在自己的終端機裡打一條指令來批准，有時間限制。批准只針對那一條指令，不是針對整個 git。
- **有些 agent 永遠批不到**。`push`、開 pull request、`reset --hard`、`clean`，還有強制選項。這些由人自己執行。

為什麼不全都用詢問？因為這三組值得不同的對待。讀是免費的。寫是正常的，但必須被看到。push 或 hard reset 這種事，第一百次點擊就會放它過去。

### 把原因寫給 agent 看

一條拒絕有兩個讀者：你，和 agent。agent 更重要。它讀了訊息，決定下一步怎麼做。

訊息只寫「已拒絕」，結果不外乎兩種：agent 再試一次同樣的事，或者試更糟的辦法。好的訊息做兩件事：

1. **為什麼**被拒絕，一句話。
2. **改做什麼**。

舉例，agent 在計劃還沒批准時就寫程式碼資料夾，好的原因會說：計劃還沒批准（計劃批准是[兩道門：人在哪裡批准](5-3-two-approvals.html)的第一道門）；先寫計劃，然後停下來，請人在自己的終端機批准。agent 現在知道下一步了，就會走這條路，不去找旁門。

我把每一條拒絕都當成 agent 唯一能得到的幫助來寫。這和上一章是同一個分工：程式負責擋，文字負責教。

## 代價和陷阱 {#costs-and-traps}

**拒絕不是免費的**。拒絕得太寬，會擋住真正的工作，而 agent 吵不贏它。規則要窄，要留一條路讓人批准那些不該拒絕的事，還要看日誌，知道哪條規則在觸發。

**詢問框還是有用**。有些「需要人」的步驟我留著當提醒。但我從不把它們算作保護。一定要守住的，就用拒絕。

**規則永遠慢一步**。終端機上，新的寫法總會漏過去。對那些絕對不能碰的東西，完全不要靠規則。不要把那樣東西交給 agent（[有些東西根本不給](4-5-least-privilege.html)）。

**等級是從文字猜的**。程式按指令的字面判斷，不是按它做了什麼。一個看起來無害的指令，放行之後也可能造成傷害。

**我沒有批准疲勞的數字**。人不看就點允許，這是我和很多人看到的，也是平台文件提醒過的。我沒有量過有多頻繁。

## 業界怎麼說 {#industry}
{status: industry}

VS Code 的 security 頁面建議用沙箱，不要只靠批准規則，並建議把自動批准限定在會話範圍，不要開到工作區或使用者層級。它說模型輔助的權限「不是安全邊界」（[security](https://code.visualstudio.com/docs/copilot/security)）。這和本章一致：詢問是方便，拒絕是規則，隔離比兩者都強。

隔離也從根上解決批准疲勞。在沙箱裡，agent 可以不問就被允許做更多事，詢問框就少了。Anthropic 說，它內部使用 Claude Code 時，沙箱「安全地減少了 84% 的權限提示」，而且要同時有檔案系統和網路的隔離才行（[Claude Code sandboxing](https://www.anthropic.com/engineering/claude-code-sandboxing)）。這是 Anthropic 對自己工具的數字；VS Code 提供的沙箱我沒有測過。

## 什麼時候可以刪掉 {#when-to-delete-it}
{status: industry}

我在終端機上寫的拒絕規則，是因為我沒有真正的沙箱。如果你的 agent 跑在容器或鎖死的環境裡，只能碰到你選好的東西，大部分規則就可以刪；邊界已經做了這份工作。按後果分級則留著，因為它是一種想法，不是一個功能。

如果平台讓你在它自己的權限設定裡寫拒絕，使它在每種模式下都有效，就把你的 hook 規則搬過去，原因保留。

::: prompt
/harness-rookie-wondering 我讀完了「詢問不是限制」這一章。請教我這個 harness 怎麼處理權限：為什麼「先問」不是限制（主題 8）、它怎麼按後果分級、git 指令怎麼處理，以及終端機怎麼防護（主題 5）。帶我打開真實的規則和拒絕訊息，讓我看 agent 被拒絕時看到什麼。
:::
