讀這一章，你需要讀過 [指令與 skill：只載入需要的](3-3-instructions-and-skills.html)。規則、規則的負責人和審查，在 [落地與治理](7-4-rollout-and-governance.html)。

## 一句話 {#in-one-sentence}

agent 做得越多，人的工作就越往上移，最後剩下四個判斷：做什麼、什麼被允許、在哪裡說好、結果好不好。新同事需要的是一個習慣和一個真實的任務，而不是整套導覽。

## 給主管 {#for-leaders}

- **要做的決定**：決定團隊裡這四個判斷各由誰來做，並決定新人從一個習慣和一個真實的任務開始。
- **風險**：我沒有數字，但能說出一個風險：如果第一個小時就是整套導覽，新人會認定這套設定很重，然後回到原本的做法。另外，一套要每個人都讀了規則才成立的設定，比一套自己就會拒絕危險事情的設定弱。
- **做對的成本**：每個新人一個小時，再加上從團隊自己的工作裡挑一個小任務的時間。
- **可以問團隊**：「誰決定什麼是允許的、哪裡必須有人說好、結果好不好？新人的第一個小時做什麼？」

## agent 交到一個團隊手裡，什麼變了？ {#problem}

一個人用 agent 的時候，這四件事都是他自己在做，只是沒有察覺。他知道自己要什麼、agent 可以碰什麼，會決定什麼時候停下來看，也會判斷結果好不好。可是同一套設定一旦交給一個團隊，這些工作就得分配到人，不然就沒人做。

還有一個問題，和規則無關，和人有關：**有些同事什麼都不會讀**。用 agent 本來就不是他們要的，如果第一個小時是一場演講，他們就會回到原本的做法。那麼，哪些判斷一定要留給人？新人，包括那位什麼都不讀的同事，又該怎麼開始？

回答之前，我該先誠實交代自己的位置。我的設定是為一個人建的，也沒有帶著測量做過團隊落地，所以下面講的，是根據這套設定已經在做的事和我自己的使用設計出來的。哪些只是我的建議，我會標出來。

## 留給人的事，和新人怎麼開始 {#how-it-works}

### 留給人的事

先說人還要做什麼。agent 做得越多，人的工作就越往上移，離開打字，走向四個 agent 沒辦法替你做的判斷。

::: figure 7-1-person-moves-up

1. **做什麼**。請求本來就模糊，還會一直變，所以要由人確認那一頁說明「做完」是什麼意思（[需求由 agent 寫，人確認](5-2-requirements.html)）。
2. **什麼被允許**。也就是規則，以及誰有權放行。誰擁有規則、誰審查改動，是 [落地與治理](7-4-rollout-and-governance.html) 的主題。
3. **在哪裡說好**。就是那些花錢、授權或無法復原的點（[兩道門：人在哪裡批准](5-3-two-approvals.html)）。
4. **結果好不好**。agent 的報告可能是錯的，所以要由人來決定，或由人信任的檢查來決定（[模型能檢查模型嗎](5-6-model-checks-model.html)）。

這四個判斷，團隊都需要，可是其中第二個，沒有哪個工具會替你來定。

### 第一個小時，不是整套導覽

這些判斷由誰來做定下來之後，緊接著的問題是：新人第一天該看到什麼？這裡最要避免的失敗，是整套導覽。如果第一天就給新人看兩道門（[兩道門：人在哪裡批准](5-3-two-approvals.html)）、一個看板（[同時管十件事：並行的是任務](7-2-many-tasks.html)）、一個知識庫和報告，他得到的印象就是這很重（[30 分鐘搭一個最小 harness](0-2-minimal-harness.html)）。比較好的第一個小時有三部分。

1. 一套會自己檢查的引導式設定。一個 skill 帶新人一步一步走（安裝、他們的名字和語言、倉庫、知識庫），每走一步就執行一次檢查，所以新人不會一直懷疑到底有沒有成功。
2. 一個小的真實任務，來自團隊自己的工作。在我的設定裡，第一堂課以一個練習任務結束，它的情境是一個檔案，團隊可以換成自己的。這樣一來，新人練習用的就是他們真的會碰的程式碼，而不是玩具。
3. 一個能問為什麼的地方。新人如果能請 harness 一邊打開真實的檔案，一邊講清楚這是怎麼回事，就不需要有人坐在旁邊。

### 不在乎的那位同事

剩下的，就是那位不在乎的同事。對他，我會要求一個習慣，而不是一種心態：說出你要做什麼，並為它開一個任務。其餘由設定來承擔。不管這個人有沒有讀過規則，危險的命令都會被拒絕；不管他記不記得為什麼，寫入都需要批准。說到底，一個靠每個人都讀規則才行的 harness，是比較差的 harness。至於對一個沒有選擇它的團隊，這樣做的效果如何，這一點我沒有量過。

### 要學什麼，要跳過什麼

那一個習慣之外，大家該花多少心力學？**學那些不變的問題**：該信誰、怎麼知道是對的、agent 該知道什麼、怎麼拆工作、要花多少。每個月都在變的就跳過，例如某一個工具的設定名稱、每個新外掛系統的細節、這週哪個模型最好。遇到一個新東西，花一個小時了解它是什麼、回答的是哪一個舊問題，就夠了。確切的格式，需要時再去查。

## 第一個小時要付出什麼，又會在哪裡出錯 {#costs-and-traps}

引導式的第一個小時需要有人維護：程式碼一變，練習任務和檢查就會過期，所以總得有人負責。

就算還沒過期，任務本身也可能挑錯。光是小而真實還不夠，最好還容得下錯，這樣新人犯了錯只要重試一次，而不是毀掉一天。

那一個習慣也有限度：它能讓人開始，卻不會永遠夠用。時間久了，他們會碰上門和報告，所以第一個小時不該把它們藏起來。

最後，第一個小時和那一個習慣，是照一個人的用法設計出來的，不是根據團隊的資料，新人接不接受，我也沒有量過。請把它們當成要檢查的起點，不要當成結果。

## 什麼時候可以刪掉引導 {#when-to-delete-it}

這套引導式設定之所以存在，是因為安裝和設定 harness 要很多步。如果設定縮成一行命令，或由平台來做，引導就可以拿掉。四個判斷卻不會消失，因為不管 agent 做多少，它們都是留給人的。
