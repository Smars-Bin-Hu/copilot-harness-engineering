读这一章之前，需要先读过[指令与 skill：只加载需要的](3-3-instructions-and-skills.html)。规则、规则的负责人和审查，放在[落地与治理](7-4-rollout-and-governance.html)里讲。

## 一句话 {#in-one-sentence}

agent 做得越多，人的工作就越往上移，最后剩下四个判断：做什么、什么被允许、在哪里点头、结果好不好。新同事需要的是一个习惯和一个真实的任务，而不是把整套东西走一遍。

## 写给管理者 {#for-leaders}

- **要拍板的事**：定下团队里这四个判断各由谁来做，并且定下新人从一个习惯和一个真实任务开始。
- **风险**：我没有数据，但能说出一个风险：要是第一个小时就把整套东西走一遍，新人会觉得这套配置很重，转头回到老办法。另外，要靠每个人都读规则才成立的配置，比自己就能拒绝危险操作的配置更弱。
- **做对的代价**：每个新人一个小时的上手时间，再加上从团队自己的工作里挑一个小任务的时间。
- **可以问团队**：“谁来决定什么被允许、哪里必须有人点头、结果好不好？新人的第一个小时做什么？”

## agent 交到一个团队手里，什么变了？ {#problem}

一个人用 agent 的时候，四件事都是他自己在做，只是没有察觉。他知道自己要什么、agent 可以动什么，会决定什么时候停下来看一眼，也会判断结果好不好。可同一套配置一旦交给一个团队，这几件事就得分派到人，否则就没人做。

还有一个问题，和规则无关，和人有关：**有些同事什么都不会读**。他们没要求过用 agent，要是第一个小时是一场讲座，他们就回到原来的做法去了。那么，哪些判断必须留给人？新人，包括那位什么都不读的同事，又该怎么上手？

回答之前，我得先把自己的位置说清楚。我的配置是为一个人搭的，也没有带着测量去做过团队落地，所以下面讲的，是根据这套配置现在已经能做的事和我自己的使用经验设计出来的。只是建议的地方，我会说明。

## 留给人的事，和新人怎么上手 {#how-it-works}

### 留给人的事

先说人是干什么的。agent 做得越多，人的工作就越往上移，离开敲键盘，转向四个 agent 没法替你做的判断。

::: figure 7-1-person-moves-up

1. **做什么**。需求是含糊的，还会变，所以要由人来确认那一页说明“做完”是什么意思的文档（[需求由 agent 写，人确认](5-2-requirements.html)）。
2. **什么被允许**。也就是规则，以及谁可以让某件事通过。谁负责规则、谁审查改动，是[落地与治理](7-4-rollout-and-governance.html)的主题。
3. **在哪里点头**。就是那些花钱的、授予权力的、做了就撤不回的地方（[两道门：人在哪里审批](5-3-two-approvals.html)）。
4. **结果好不好**。agent 的报告可能是错的，所以要由人来判断，或者由人信得过的检查来判断（[模型能检查模型吗](5-6-model-checks-model.html)）。

这四个判断，团队都需要，可其中第二个，没有哪个工具会替你来定。

### 第一个小时，不是把整套东西走一遍

这些判断由谁来做定下来之后，紧接着的问题是：新人第一天该看到什么？这里最该避开的失败，是把整套东西走一遍。要是第一天就把两道门（[两道门：人在哪里审批](5-3-two-approvals.html)）、看板（[同时管十件事：并行的是任务](7-2-many-tasks.html)）、知识库和报告全摆出来，新人得到的印象就是这套东西很重（[30 分钟搭一个最小 harness](0-2-minimal-harness.html)）。更好的第一个小时有三部分。

1. 一套带引导、自己会检查的配置。一个 skill 带着新人一步一步走（安装、名字和语言、仓库、知识库），每走一步都跑一次检查，所以新人不用一直猜到底成功了没有。
2. 一个来自团队自己工作的小而真实的任务。在我的配置里，第一课以一个练习任务收尾，任务的场景是一个文件，团队可以换成自己的。这样新人练手用的，就是他们以后真会动的代码，而不是玩具。
3. 一个能问“为什么”的地方。新人如果能让 harness 打开真实的文件，给自己讲清楚它是怎么回事，就不需要有人坐在旁边。

### 不在乎的那位同事

剩下的，就是那位不在乎的同事。对他，我只要求一个习惯，不要求一种心态：说出你要做什么，然后为它开一个任务。其余的由配置来扛。不管这个人读没读过规则，危险命令都会被拒绝；不管他还记不记得为什么，写入都需要审批。说到底，要靠每个人都读规则才成立的 harness，是更差的 harness。至于放到一个不是自己选择它的团队里效果如何，这一点我没有测过。

### 学什么，跳过什么

那一个习惯之外，人到底该学多少？**学那些不变的问题**：该信任谁，怎么知道结果对不对，agent 该知道什么，怎么拆分工作，要花多少钱。每个月都在变的东西就跳过，比如某个工具的设置名、每个新插件系统的细节、这周哪个模型最好。遇到一个新东西，花一个小时弄清它是什么、回答的是哪个老问题，就够了。具体的格式，等用到时再查。

## 第一个小时要付出什么，又会在哪里出错 {#costs-and-traps}

带引导的第一个小时需要有人维护：代码一变，练习任务和检查就会过期，所以得有人负责它们。

就算还没过期，任务本身也可能选错。光是小而真实还不够，最好还容得下错，这样新人做错了只是重来一次，而不是搭进去一整天。

那一个习惯也有限度：它能让人开始，却不是永远够用。时间一长，他们会碰上关卡和报告，所以第一个小时不该把这些藏起来。

最后，第一个小时和那一个习惯，靠的是一个人的使用，而不是团队的数据，新人接不接受，我也没有测过。请把它们当作要验证的起点，不要当结果。

## 什么时候可以删掉引导 {#when-to-delete-it}

这套带引导的配置之所以存在，是因为安装和配置 harness 要走很多步。如果配置缩成一条命令，或者平台替你做了，这个引导就可以删。四个判断却不会消失，因为不管 agent 做多少，它们都是留给人的。
