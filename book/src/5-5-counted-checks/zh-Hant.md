讀這一章，你需要讀過 [慎用子 agent](2-3-subagents.html)，它解釋了為什麼有一個上下文獨立的檢查者值得擁有。這裡的問題不一樣：你怎麼知道檢查真的發生了，而且真的通過了？

## 一句話 {#in-one-sentence}

要讓檢查算數，由程式來計算通過。不要接受 agent 說「我檢查過了」。

## 給主管 {#for-leaders}

- **要做的決定**：決定「檢查過」指的是程式計數的紀錄，不是 agent 的一句話。要連續通過幾次，由人設定，也只有人能豁免這條規則。
- **風險**：「我讓人檢查過了，通過了」這句話沒辦法測試。agent 可能跳過了檢查、檢查的是舊版本，或把 FAIL 讀成通過。豁免也可能變成習慣，那樣上限就只是裝飾。
- **做對的成本**：額外的檢查每次都花用量，而計數器需要一個包含對的東西的工作指紋。在我的設定裡，上限是 n 次檢查再加兩次，這是個例子，不是調過的值。沒有任何機制時，就要求給出指令和它的結果。
- **可以問團隊**：「對最近上線的那次改動，給我看那個確切版本上有執行檢查的紀錄。」

## 問題 {#problem}

假設你要求每一份工作，在寫回倉庫之前，都要通過一次獨立檢查（寫回：把做完的工作複製到真實的倉庫，見 [兩道門：人在哪裡批准](5-3-two-approvals.html)）。你把它寫進規則。agent 做完了，說：「我讓人檢查過了，通過了。」

這句話你能拿來做什麼？什麼都做不了。它可能是真的。agent 也可能跳過了檢查，或檢查的是工作的舊版本，或因為想快點結束，把 FAIL 讀成了通過。聊天裡的一句話，是 agent 產出最便宜的東西，也是你唯一沒辦法測試的東西。

這一章講的是：檢查有沒有發生、是不是對這個版本、結論是什麼。它是對過程的保證，不是對工作品質的保證。解法和 [提示裡的規則只是請求](4-1-requests-and-rules.html) 是同一個想法：不要問 agent 做了沒有。讓那件事留下程式讀得懂的痕跡，由程式來決定。

## 原理 {#how-it-works}

### 檢查者的答案由程式存下來，不是由 agent

檢查者回答時，它的答案由一個 hook 在寫出的當下就寫進檔案。agent 不能編輯那個檔案。答案的第一行是固定的：PASS 或 FAIL（[慎用子 agent](2-3-subagents.html)）。所以「有沒有檢查過、結論是什麼」就成了一個關於檔案的問題，一個小程式就能回答。

### 數連續的通過，而且是對確切的那份工作

單單一次通過很弱。檢查者是個模型，所以它可能運氣好，也可能錯。連續通過好幾次，能降低單次運氣好的機會。它去不掉每次運行都共有的盲點，因為檢查者是同一種模型（[模型能檢查模型嗎](5-6-model-checks-model.html)）。所以需要通過幾次，由人來說：**連續 n 次通過**。在我的設定裡，人把它寫在 prompt 裡，例如「連續兩次通過」。agent 不能替自己寫。

計數由程式做，做法是這樣：從最近一次檢查開始往回走。數連續的 PASS。遇到第一個 FAIL 就停。FAIL 後面通常跟著一次編輯，編輯會改變工作，所以更早的通過就不再算：n 次通過必須都是對同一個版本。而且只有當它檢查的版本**就是現在這個樣子的工作**，才算一次 PASS。

::: figure 5-5-pass-counter

「確切」需要定義。程式會對工作取一個**指紋**：對結果檔案、需求和計畫算出的 hash（內容一變，這段短碼就跟著變）。每次檢查都記下它看到的指紋。如果現在的指紋不同，那次檢查講的是較舊的工作，所以不算。

有兩個細節讓它保持誠實：

- **指紋裡只放會改變結果的東西**。進度備註、紀錄和檢查者自己的紀錄不放進去。不然勾掉一個待辦項目就會取消一次通過，計數器白白重設。
- **需求或計畫一改，計數也重設**。對舊計畫的通過，對新計畫說不了什麼。

然後計數決定下一步能不能走。把工作寫回倉庫的那一步，在通過次數達到 n 之前會被拒絕。agent 沒有路可以繞過去：要讓計數增加，唯一的辦法是讓工作再被檢查一次。

### 檢查次數的上限

檢查者可能一直找得到東西。如果每一輪都帶來新的發現，循環就永遠不會結束。所以有一個**上限**：n 次檢查加一點餘裕（在我的設定裡是多兩次；是個例子，不是調過的值）。用完了還沒有足夠的通過，agent 就停下來，告訴人最後的發現在哪裡。

人接著選擇，在終端機裡打一段碼：允許更多次檢查，或這個版本豁免這條規則。

### 豁免

**豁免**讓目前的版本在通過次數不夠的情況下過關。人需要它：有時最後的發現只是措辭，或檢查者錯了，人已經讀過工作，也滿意了。三條規則讓豁免安全：

- **只有人能給**，走 agent 碰不到的管道（[兩道門：人在哪裡批准](5-3-two-approvals.html) 說了怎麼做）。
- **只涵蓋一個版本**。工作再變，豁免就結束，計數重新開始。
- **會留下紀錄**。之後你能看到，這個版本是靠人的決定過關的，不是靠通過。

相反的情況還有第二個工具。如果人判斷某一次檢查是錯的，可以把它放到一邊。它就不再算數，既不算用掉的一次檢查，也不算 FAIL。

### 沒有這些機制

如果你沒有檢查者 agent，也要保留這個想法：不要接受「我檢查過了」。請 agent 貼上它執行的指令和結果，自己讀結論。之後只要有任何編輯，就再問一次。

### 檢查開著，卻什麼都沒檢查

最陰險的失敗是沉默：檢查是開著的，agent 就是從來不呼叫檢查者。因為什麼都沒執行，所以從來沒有記錄過任何 FAIL。prompt 裡的規則抓不到這種情況，因為忘記的正是 agent。

所以檢查放在 agent 必須經過的地方：它想停下來的那一刻。那一刻的 hook（[Hooks：每次呼叫都會經過的執行點](2-2-hooks.html)）會拿狀態和事實對照。如果檢查是開著的，卻沒有任何檢查，或最後一次檢查之後工作又變了，它就擋一次，叫 agent 補上。然後寫回的門（[兩道門：人在哪裡批准](5-3-two-approvals.html)）無論如何仍然關著，因為計數還是低於 n。

### 檢查者交出什麼

計數只會和被計的東西一樣好，所以檢查者的答案有固定的形狀，就像 [慎用子 agent](2-3-subagents.html) 裡那樣。答案之後，有一個腳本檢查這個形狀。檔案或行號不存在的發現，會被丟掉。一個什麼都不剩的 FAIL 是**無效**的：這次檢查會退回去，所以含糊的檢查者不會吃掉額度。

腳本檢查的是形狀，不是判斷。檢查者對不對，仍然只是一個模型的意見。[模型能檢查模型嗎](5-6-model-checks-model.html) 接著談這點。

## 代價和陷阱 {#costs-and-traps}

**指紋要對**。放得太多，每個小編輯都會取消通過，你又得為檢查付錢。放得太少，改動就會從通過旁邊溜過去。我沒找到完美的清單；我靠問「這個檔案會不會改變工作是什麼？」來決定。

**計數出來的通過，只和檢查者一樣強**。計數器證明的是，在這個確切的版本上有發生過檢查。它不證明檢查者是對的。兩個檢查者對同一份工作可能給出不同的結論（[模型能檢查模型嗎](5-6-model-checks-model.html)）；這是對重要的改動允許連續不只一次通過的原因之一。檢查者多常出錯，我沒有量過。

**它不能代替真的去執行**。唯讀的檢查者算出來的通過，是關於閱讀的通過。對 agent 能執行的檢查（測試、linter），見 [讓 agent 能檢查自己的活](5-4-self-checks.html)。那裡有同樣的警告：除非你看得到指令和它的輸出，否則「通過」的測試意義不大。Anthropic 的指南說得很直接：「光是『所有測試都通過』，告訴你的很少」（[Best practices](https://code.claude.com/docs/en/best-practices)）。

**豁免可能變成習慣**。如果每次碰到上限，人都豁免，上限就只是裝飾。豁免的紀錄，就是你察覺這件事的辦法。

## 什麼時候可以刪掉 {#when-to-delete-it}

這樣的計數器存在，是因為平台沒有內建「這份工作在這個版本上，被獨立檢查過 n 次」這個概念。如果平台加上了，而且紀錄是 agent 改不了的，就用它，把計數器拿掉。想法不會退役：由人，不是 agent，決定什麼算檢查過。
