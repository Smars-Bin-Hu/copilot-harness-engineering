讀這一章之前，你需要讀過 [慎用子 agent](2-3-subagents.html)，它解釋了為什麼值得有一個上下文獨立的檢查者。這一章問的是另一件事：你怎麼知道一次檢查真的發生了，而且真的通過了？

## 一句話 {#in-one-sentence}

要讓一次檢查算數，通過的次數就得由程式來數，不能聽 agent 說一句「我檢查過了」就算。

## 給主管 {#for-leaders}

- **要做的決定**：決定「檢查過」指的是一筆由程式計數的紀錄，而不是 agent 的一句話。要連續通過幾次由人設定，也只有人能豁免這條規則。
- **風險**：「我讓人檢查過了，通過了」這句話沒辦法驗證，因為 agent 可能跳過了檢查、檢查的是舊版本，或把 FAIL 讀成了通過。豁免也可能變成習慣，那樣上限就只是裝飾。
- **做對的成本**：多出來的檢查每次都要花用量，計數器還需要一個把該放的東西都放進去的工作指紋。在我的設定裡，上限是 n 次檢查再加兩次，這只是個例子，不是調過的值。就算什麼機制都沒有，也可以要求給出指令和它的結果。
- **可以問團隊**：「拿最近上線的那次改動來說，給我看那個確切版本上有執行檢查的紀錄。」

## 為什麼「我讓人檢查過了」什麼也證明不了 {#problem}

假設你要求每一份工作在寫回倉庫之前，都要通過一次獨立檢查（寫回就是把做完的工作複製到真實倉庫的那一步，見 [兩道門：人在哪裡批准](5-3-two-approvals.html)）。你把這一條寫進了規則。agent 做完以後告訴你：「我讓人檢查過了，通過了。」

這句話你能拿來做什麼？什麼都做不了。它可能是真的，但 agent 也可能跳過了檢查，或檢查的是工作的舊版本，又或者因為想快點結束，把 FAIL 讀成了通過。聊天裡的一句話，是 agent 產出最便宜的東西，偏偏也是你唯一沒辦法驗證的東西。

這句話底下其實是三個問題：檢查有沒有發生、對的是不是這個版本、結論是什麼。回答了它們，你得到的是對過程的保證，而不是對工作品質的保證。要得到這個保證，用的是和 [提示裡的規則只是請求](4-1-requests-and-rules.html) 同一個想法：別去問 agent 有沒有做那件事，而是讓那件事留下程式讀得懂的痕跡，再由程式來決定。那麼，這個痕跡是什麼，程式又拿它做什麼？

## 讓程式來記錄檢查、清點通過 {#how-it-works}

### 檢查者的答案由程式存下來，不是由 agent

第一個痕跡，就是檢查者的答案本身。檢查者一回答，hook 就把答案原封不動寫進一個 agent 改不了的檔案。答案的第一行又是固定的，只能是 PASS 或 FAIL（[慎用子 agent](2-3-subagents.html)），所以「有沒有檢查過、結論是什麼」就變成一個關於檔案的問題，一個小程式就能回答。

### 對確切的那份工作，數連續通過的次數

只記下一次通過，證據還是很弱，因為檢查者是個模型，它可能剛好運氣好，也可能出錯。要求連續通過好幾次，能降低工作靠一次運氣好的結論過關的機會。不過，每次運行都共有的盲點，它去不掉，因為這些檢查者都是同一種模型（[模型能檢查模型嗎](5-6-model-checks-model.html)）。所以幾次才夠，是一個判斷，由人來做：**連續 n 次通過**。在我的設定裡，人把這個數字寫在 prompt 裡，例如「連續兩次通過」。agent 不能替自己寫。

計數由程式來做。它從最近一次檢查開始往回走，一路數連續的 PASS，直到遇到第一個 FAIL 為止。之所以停在那裡，是因為 FAIL 後面通常跟著一次編輯，編輯改變了工作，更早的那些通過也就不再算數。換句話說，這 n 次通過都得針對同一個版本，而且不是隨便哪個版本：只有檢查的**就是現在這個樣子的工作**，那次 PASS 才算。

::: figure 5-5-pass-counter

可是要怎麼判斷工作還是「現在這個樣子」？程式會對工作取一個**指紋**，也就是對結果檔案、需求和計畫算出的 hash（內容一變，這段短碼就跟著變）。每次檢查都會記下它看到的指紋，所以如果現在的指紋不一樣了，那次檢查講的就是較舊的工作，不算數。

計數誠不誠實，取決於指紋裡放了什麼。只有會改變結果的東西才放進去，所以進度備註、日誌和檢查者自己的紀錄都不放。要是放進去了，勾掉一個待辦項目就會取消一次通過，計數器白白重設。需求和計畫則不同，它們在指紋裡，所以改了其中任何一個，計數也會重設。針對舊計畫拿到的通過，對新計畫說不了什麼。

接著，這個計數決定下一步能不能走。把工作寫回倉庫的那一步，在通過次數達到 n 之前會被拒絕。agent 沒有路可以繞過去，因為要讓計數增加，唯一的辦法就是讓工作再被檢查一次。

### 檢查次數的上限

要是通過次數一直到不了 n 呢？檢查者一直找得到東西的時候，就會這樣。如果每一輪都帶來新的發現，這個循環就永遠不會結束。所以要有一個**上限**：n 次檢查，再加一點餘裕（在我的設定裡是多兩次，只是個例子，不是調過的值）。檢查次數用完了，通過次數還不夠，agent 就停下來，告訴人最後那些發現在哪裡。接下來由人在終端機裡打一段碼來選：允許再多檢查幾次，或者讓這個版本豁免這條規則。前一個選項好懂，就是讓檢查者多跑幾輪；後一個需要多說幾句。

### 豁免

所謂**豁免**，就是讓目前的版本在通過次數不夠的情況下也能過關。人確實需要它，因為有時最後的發現只是措辭，或者檢查者錯了，而人已經讀過這份工作，也滿意了。讓豁免安全的有三條規則。豁免只有人能給，而且走的是 agent 碰不到的管道（怎麼做，見 [兩道門：人在哪裡批准](5-3-two-approvals.html)）。豁免也只涵蓋一個版本，所以工作一變，豁免就結束，計數重新開始。它還會留下一筆紀錄，之後翻看時你能看到，這個版本是靠人的決定過關的，不是靠通過次數。

豁免之外，人手上還有一個方向相反的工具：它不是讓通過次數不夠的版本過關，而是拿掉人判斷為錯的某一次檢查。人把那次檢查放到一邊以後，它就不再算數，既不算用掉的一次檢查，也不算一個 FAIL。

### 沒有這些機制

上面這些，都假設有一個檢查者 agent，還有替它數通過次數的程式。如果你沒有檢查者 agent，這個想法照樣成立：不要接受「我檢查過了」。請 agent 貼上它執行的指令和結果，結論你自己讀。之後只要有任何編輯，就再問一次。

### 檢查開著，卻什麼都沒檢查

回到有檢查者的設定。前面數的一切，都假設 agent 真的呼叫了檢查者。最難察覺的失敗恰恰是沉默：檢查是開著的，agent 卻從來不呼叫檢查者。因為什麼都沒執行，所以一個 FAIL 也不會被記下來。寫在 prompt 裡的規則也抓不到這種情況，因為忘了這件事的正是 agent。

所以檢查要放在 agent 必須經過的地方，也就是它想停下來的那一刻。那一刻的 hook（[Hooks：每次呼叫都會經過的執行點](2-2-hooks.html)）會拿狀態和事實對照。如果檢查開著卻沒有檢查過，或最後一次檢查之後工作又變了，它就擋一次，叫 agent 補上。不管 agent 怎麼回應這次提醒，寫回的門（[兩道門：人在哪裡批准](5-3-two-approvals.html)）都還關著，因為計數還是低於 n。

### 檢查者交出什麼

計數靠不靠得住，取決於被計的是什麼，所以檢查者的答案有固定的格式，就像 [慎用子 agent](2-3-subagents.html) 裡那樣。答案交出來以後，有一個腳本檢查這個格式，把檔案或行號不存在的發現丟掉。丟完之後什麼都不剩的 FAIL 是**無效**的：這次檢查會退回去，含糊的檢查者就不會白白吃掉額度。

不過腳本檢查的是格式，不是判斷。檢查者對不對，仍然只是一個模型的意見，這正是 [模型能檢查模型嗎](5-6-model-checks-model.html) 要談的問題。

## 計數要付出什麼，又證明不了什麼 {#costs-and-traps}

頭一件要做對的事是指紋。放進去的東西太多，每個小編輯都會取消通過，你又得為檢查再付一次錢；放得太少，改動就會從一次通過旁邊溜過去。我沒找到一份完美的清單，所以靠問自己「這個檔案會不會改變工作是什麼？」來決定。

就算指紋取對了，計數出來的通過也只和檢查者一樣可靠。計數器證明的是在這個確切的版本上發生過檢查，並不證明檢查者是對的。兩個檢查者對同一份工作可能給出不同的結論（[模型能檢查模型嗎](5-6-model-checks-model.html)）。所以對重要的改動，可以把連續通過的次數設成不只一次，這是原因之一。不過檢查者到底多常出錯，我並沒有量過。

計數出來的通過，也代替不了真的去執行。唯讀的檢查者給出的通過，是關於閱讀的通過。至於 agent 能執行的檢查，例如測試、linter，見 [讓 agent 能檢查自己的活](5-4-self-checks.html)。那裡的警告同樣適用：除非你看得到指令和它的輸出，否則「通過」的測試意義不大。Anthropic 的指南說得很直接：「光是『所有測試都通過』，告訴你的很少」（[Best practices](https://code.claude.com/docs/en/best-practices)）。

最後一個陷阱在人這一邊，不在 agent 那邊：豁免可能變成習慣。如果每次碰到上限，人都選擇豁免，上限就只是裝飾。豁免的紀錄，就是你察覺這件事的辦法。

## 什麼時候可以刪掉計數器 {#when-to-delete-it}

這樣的計數器之所以存在，是因為平台沒有內建「這份工作在這個版本上，被獨立檢查過 n 次」這個概念。如果平台加上了，而且紀錄是 agent 改不了的，就用平台的，把計數器拿掉。不過背後的想法不會退役：什麼算檢查過，由人來決定，而不是 agent。
