读这一章之前，你要读过[慎用子 agent](2-3-subagents.html)，它讲了为什么值得有一个上下文独立的检查者。这一章问的是另一件事：你怎么知道一次检查真的发生了，而且真的通过了？

## 一句话 {#in-one-sentence}

一次检查要算数，通过的次数就得由代码来数，不能听 agent 说一句“我检查过了”就算。

## 写给管理者 {#for-leaders}

- **要拍板的事**：决定“检查过”指的是一条由代码计数的记录，而不是 agent 的一句话。连续要通过多少次由人来定，也只有人能豁免这条规则。
- **风险**：“我让人检查过了，通过了”这句话没法验证，因为 agent 可能跳过了检查，可能检查的是旧版本，也可能把 FAIL 看成了通过。豁免还可能变成习惯，那样上限就只是摆设。
- **做对的代价**：多出来的检查每次都要花用量，计数器还需要一个把该放的东西都放进去的工作指纹。在我的配置里，上限是 n 次检查再加两次，这只是个例子，不是调优过的值。就算什么机制都没有，也可以让 agent 给出命令和它的结果。
- **可以问团队**：“拿最近上线的那次改动来说，给我看那个确切版本上做过检查的记录。”

## 为什么“我让人检查过了”什么也证明不了 {#problem}

假设你想让每份工作在写回仓库之前，都通过一次独立检查（写回就是把做完的工作复制进真实仓库的那一步，见[两道门：人在哪里审批](5-3-two-approvals.html)）。你把这一条写进了规则。agent 做完以后告诉你：“我让人检查过了，通过了。”

这句话你能拿来做什么？什么也做不了。它可能是真的，可 agent 也可能跳过了检查，或者检查的是工作的旧版本，又或者因为想早点收工，把 FAIL 看成了通过。聊天里的一句话，是 agent 产出的最廉价的东西，偏偏也是你唯一没法验证的东西。

这句话底下其实是三个问题：检查有没有发生，对着的是不是这个版本，结论是什么。回答了它们，你得到的是对过程的保证，而不是对工作质量的保证。要得到这个保证，用的是和[提示里的规则只是请求](4-1-requests-and-rules.html)同一个思路：别去问 agent 有没有做那件事，而是让那件事留下代码读得懂的痕迹，再由代码来判断。那么，这个痕迹是什么，代码又拿它做什么？

## 让代码来记录检查、清点通过 {#how-it-works}

### 检查者的回答由代码保存，不由 agent 保存

第一个痕迹，就是检查者的回答本身。检查者一回答，hook 就把回答原样写进一个 agent 改不了的文件。回答的第一行又是固定的，只能是 PASS 或 FAIL（见[慎用子 agent](2-3-subagents.html)），所以“检查发生了没有，结论是什么”就变成了一个关于文件的问题，一个小程序就能回答。

### 对确切的那份工作，数连续通过的次数

只记下一次通过，证据还是很弱，因为检查者是个模型，它可能碰巧走运，也可能出错。要求连续通过几次，能降低工作靠一次走运的结论混过去的可能。不过，每次运行共有的盲区，它消除不了，因为这些检查者都是同一类模型（见[模型能检查模型吗](5-6-model-checks-model.html)）。所以几次才够，是一个判断，由人来做：**连续通过 n 次**。在我的配置里，人把这个数写在 prompt 里，比如“连续通过两次”。agent 不能替自己写。

计数由代码来做。它从最近一次检查开始往回走，一路数连续的 PASS，直到碰上第一个 FAIL 为止。之所以在那里停下，是因为 FAIL 之后通常跟着一次编辑，编辑改变了工作，更早的那些通过也就不再算数。换句话说，这 n 次通过都得对着同一个版本，而且不是随便哪个版本：只有检查的**恰好是工作现在的样子**，那次 PASS 才算。

::: figure 5-5-pass-counter

可“恰好”是什么意思？代码会给工作取一个**指纹**，也就是对结果文件、需求和计划做的哈希（内容一变就跟着变的一小段码）。每次检查都会记下它看到的指纹，所以如果现在的指纹不一样了，那次检查说的就是更早的工作，不算数。

计数诚实不诚实，取决于指纹里放了什么。只有会改变结果的东西才放进去，所以进度笔记、日志和检查者自己的记录都不放。要是放进去了，勾掉一个待办项就会抵销一次通过，计数器白白归零。需求和计划则不同，它们在指纹里，所以改了其中任何一个，计数也会归零。对着旧计划拿到的通过，对新计划说明不了什么。

这个计数接着管住下一步。把工作写回仓库的那一步，在通过次数达到 n 之前会被拒绝。agent 绕不过去，因为要提高计数，唯一的办法就是让工作再被检查一次。

### 检查次数的上限

要是通过次数一直到不了 n 呢？检查者一直能挑出点什么的时候，就会这样。如果每一轮都有新的发现，这个循环就永远结束不了。所以要有一个**上限**：n 次检查，再加一点余量（在我的配置里是多两次，只是个例子，不是调优过的值）。检查次数用完了，通过次数还不够，agent 就停下来，告诉人最后那些发现在哪里。接下来由人在终端里敲码来选：允许再多检查几次，或者对这个版本豁免这条规则。前一个选项好懂，就是让检查者多跑几轮；后一个需要多说几句。

### 豁免

所谓**豁免**，就是让当前版本在通过次数不够的情况下也能放行。人确实需要它，因为有时候最后的发现只是措辞问题，或者检查者错了，而人已经读过这份工作，也满意了。让豁免安全的有三条规则。豁免只有人能给，而且走的是 agent 够不着的渠道（怎么做，见[两道门：人在哪里审批](5-3-two-approvals.html)）。豁免也只管一个版本，所以工作一变，豁免就失效，计数从头开始。它还会留下一条记录，以后翻看时你能看出，这个版本是靠人的决定过去的，不是靠通过次数。

豁免之外，人手里还有一个方向相反的工具：它不是让通过次数不够的版本放行，而是拿掉人判断为错的某一次检查。人把那次检查搁置以后，它就不再算数，既不算用掉的一次检查，也不算一个 FAIL。

### 没有这套机制时

上面这些，都假定有一个检查者 agent，还有替它数通过次数的代码。如果你没有检查者 agent，这个想法照样成立：不接受“我检查过了”。让 agent 贴出它运行的命令和结果，结论你自己读。之后只要有编辑，就再问一遍。

### 检查开着，却什么都没检查

回到有检查者的配置。前面数的一切，都假定 agent 真的调用了检查者。最隐蔽的失败恰恰是沉默：检查是开着的，agent 却从来不调用检查者。因为什么都没运行，一个 FAIL 也不会被记下。写在 prompt 里的规则也抓不住这种情况，因为忘了这件事的正是 agent。

所以检查要放在 agent 非经过不可的地方，也就是它想停下的那一刻。那一刻的 hook（见 [Hook：每次调用都会经过的执行点](2-2-hooks.html)）会把状态和事实对一对。如果检查开着却没有检查过，或者最后一次检查之后工作又变了，它就拦一次，让 agent 补上。不管 agent 怎么回应这次提醒，写回的关卡（见[两道门：人在哪里审批](5-3-two-approvals.html)）都还关着，因为计数还没到 n。

### 检查者交上来的东西

计数靠不靠得住，取决于被数的是什么，所以检查者的回答有固定的格式，和[慎用子 agent](2-3-subagents.html)里讲的一样。回答交上来以后，由脚本检查这个格式，把文件或行号不存在的发现丢掉。丢完之后什么都不剩的 FAIL 是**无效**的：这次检查退回去，含糊的检查者就不会白白吃掉预算。

不过脚本检查的是格式，不是判断。检查者对不对，仍然只是一个模型的意见，这正是[模型能检查模型吗](5-6-model-checks-model.html)要讲的问题。

## 计数要付出什么，又证明不了什么 {#costs-and-traps}

头一件要做对的事是指纹。放进去的东西太多，每个小编辑都会抵销通过，你又得为检查再付一次钱；放得太少，改动就会从一次通过旁边溜过去。我没找到一份完美的清单，所以靠问自己“这个文件会不会改变工作是什么”来决定。

就算指纹取对了，计数出来的通过也只和检查者一样可靠。计数器证明的是这个确切的版本上发生过一次检查，并不证明检查者是对的。两个检查者对同一份工作可能给出不同的结论（见[模型能检查模型吗](5-6-model-checks-model.html)）。所以对重要的改动，可以把连续通过的次数设成不止一次，这是理由之一。不过检查者到底多常出错，我并没有测过。

计数出来的通过，也代替不了真正去运行。只读的检查者给出的通过，是关于“读”的通过。至于 agent 能运行的检查，比如测试、linter，见[让 agent 能检查自己的活](5-4-self-checks.html)。那里的警告同样适用：一个“通过了”的测试，除非你能看到命令和它的输出，否则说明不了多少。Anthropic 的指南说得很直接：“光是一句‘所有测试都通过了’，本身告诉你的东西很少”（[Best practices](https://code.claude.com/docs/en/best-practices)）。

最后一个坑在人这一边，不在 agent 那边：豁免可能变成习惯。如果每次碰到上限，人都选择豁免，上限就只是摆设。豁免的记录，就是你发现这一点的办法。

## 什么时候可以删掉计数器 {#when-to-delete-it}

这样的计数器之所以存在，是因为平台没有内置“这份工作在这个版本上被独立检查了 n 次”这个概念。如果平台加上了，而且记录是 agent 改不了的，就用平台的，把计数器去掉。不过背后的想法不会退役：什么算检查过，由人来定，而不是 agent。
