这一章接在[分批学一个领域](8-4-kb-learning.html)后面。它是路线的第七步，而且永远做不完。笔记为什么一般都该带来源和日期，见[agent 该记住什么](3-5-memory.html)；这一章讲的是怎么把它用在代码上。

## 一句话 {#in-one-sentence}

知识会过期。所以每张卡片都记下它是在哪个 commit 读的；代码一变，就能列出过期的卡片，只修改动过的那几行。

## 写给管理者 {#for-leaders}

- **要拍板的事**：给知识库指定一个负责人，约定多久刷新一次过期的笔记，以及谁有权把一条笔记标成“已检查”。
- **风险**：一个曾经正确、之后再没检查过的知识库，可能比没有还糟，因为大家会信它。“已检查”的戳，只有它之前那次检查那么可靠。过期笔记的清单会漏掉被改动对象的调用方；这会让多少笔记变错，我没有测过。
- **做对的代价**：每次刷新只读代码里改动的部分，不读整个文件，每个任务最多约 20 条笔记。列出过期笔记的清单不需要读任何东西。
- **可以问团队**：“我们有多少条笔记比它所描述的代码还旧，由谁负责？”

## 问题 {#problem}

一个团队在三月写出了很好的卡片。到六月，它们所依据的文件已经改了三分之一。没人说得清哪些卡片现在是错的。于是读者对所有卡片都失去信任，知识库没人看了。一个曾经正确、之后再没检查过的知识库，可能比没有还糟，因为大家会信它。

有两种应对办法，都不行。一种是“隔一阵子全部重写”：成本和第一次建库一样高。另一种是“指望大家发现卡片不对就去改”：他们发现不了。

解法是让过期*看得见，而且花费很低*。卡片写明它读的是代码的哪个版本，脚本就能回答“什么动过了？”。这个思路不用任何工具也能试：记下一条笔记是在哪个 commit 读的，以后运行 `git diff <那个 commit>..HEAD -- <文件>`。diff 是空的，说明这条笔记的来源没变。

## 原理 {#how-it-works}

### 卡片上的版本

commit 和 sha 在[知识库：代码的诚实索引](8-1-why-a-knowledge-base.html)里讲过。**对象索引**是脚本生成的清单，列出每个对象和它的源文件。

有三个地方记着版本：

- **对象索引的每一行**，保存写卡片时源文件的 sha。
- **每张卡片**带一个标记，说明它对照代码验证过，以及是在哪个 commit 读的。这个标记告诉读者，这张卡片有没有对照代码检查过。
- **领域**记录它学习时每个仓库所在的 commit。

### 列出过期的卡片

脚本把索引每一行上的 sha，和基线分支（代码的主线）上现在的文件比较。来源变了，卡片就**过期**。来源被删除的卡片也会列出来。

::: figure 8-5-stale-cards

只有变了的卡片需要关注，所以大代码库里的小改动，对应的是一份短清单。过期卡片所占的比例，也正是适合放上看板的数字。有一个缺口要知道：清单列出的是自己的来源变了的卡片，不包括它们调用方的卡片（见[代价和坑](#costs-and-traps)）。

### 刷新：读 diff，不读文件

对每张过期卡片，agent 读的是 **diff**：自卡片写成以来，来源里到底改了什么。这比重新读整个文件便宜，还能指出卡片里哪些行可能错了。

- 如果改动没碰到卡片说的内容（注释、格式、卡片没覆盖的部分），文字保持不变。
- 如果碰到了，agent 只改被牵动的那几行。
- 然后给卡片**盖戳**：记录这张卡片已对照现在的代码检查过。戳是一种声明，所以只给 agent 真正检查过的卡片盖。给没人读过的卡片盖戳，会把一张错卡片藏到下一次改动。

一次刷新和别的任务一样：一份计划，列出每张卡片和预计要改什么；人审批；然后写回（[两道门：人在哪里审批](5-3-two-approvals.html)）。每个任务最多约 20 张卡片；更多的话，先做用得最多的。

**来源不见了的时候**，agent 先找是不是改名了。改名了，就更新路径。被删了，agent 就问人：这张卡片是删掉还是留着。留下的卡片标成“来源已不在”，它的标记变成*未知*，这样它读起来就不像检查过的知识。

### 做完的任务教会了什么

卡片还有另一种出错的方式：agent 在做任务的时候，发现某张卡片是错的或者缺了。它一边干活，一边在任务的日志里记下来。任务结束时，另有一步（我叫它**捕获**）挑出值得留下的内容，**起草**出来给人审批。没有任何东西会自己进知识库。“下个月还成立”只是模型的预测，所以人的审批才是真正的检查。

只有同时满足下面这些条件，它才会留下一条：没有它，将来的 agent 会做错；任务里有证据（一个文件和行号）；知识库里还没有记录；下个月还会成立。“这里没有值得留的”是一个好答案。该记什么的通用规则，在[agent 该记住什么](3-5-memory.html)里。

### 请求清单：代码说不出来的东西

按我自己的估计（不是测出来的），知识库里有一小部分无法从代码得到。它来自人，来自正在运行的系统。所以每个领域有一份**请求清单**：人要提供的每样东西占一行。一行有：

- 一个**类别**：*code*（不在任何仓库里的源码）、*runtime*（某个环境里的值）、*history*（要到 git 里找的东西）或 *decision*（需要某个人做出的选择）；
- 一条只读的命令或查询，人可以原样运行；
- 一个**状态**：*open*（未处理）、*answered*（已回答，记下什么时候、谁回答的、填到了哪里）或 *declined*（已拒绝，之后不再问）。

agent 在下一次停下来的时候提问，绝不在干活中途打断。这些行来自地图看不见的地方（[8.3](8-3-kb-audit.html)）：动态名字、外部名字、被删掉的来源。

人给回来的东西，写进第二个文件，叫**环境事实**：一行一条事实，比如某个作业是否启用，或者某张规则表里有什么。每行记下环境、日期、对象、当天该对象代码的 sha，以及是谁提供的。代码往前走之后，就能看出这条事实是对着更旧的代码看到的。人贴回来的内容仍然是不可信的文本：里面可能有脏数据，甚至有指令，所以要按[agent 读到的文字可能在指挥它](4-6-untrusted-input.html)里的办法对待。

### 把已有的知识库接进来

如果你已经有关于代码的笔记，可以改成这个格式。把每个 sha 设成旧笔记写成时的 commit，不要设成今天的。这样从第一天起，过期清单就是诚实的：它显示的是自笔记写成以来变了什么。旧笔记往往不写明出自哪个 commit；那就只能猜，而猜错会把过期的卡片藏起来。这件事会比听起来难。

### 测一测你自己的配置

1. 拿三张卡片，写下各自是在哪个 commit 读的。
2. 改一个源文件。列出来源变了的卡片。
3. 只按 diff 刷新。数一数你读了多少行，和整个文件比（`git diff --stat` 显示改了多少行；`wc -l` 显示文件有多少行）。
4. 往请求清单里加一行，写上类别、一条只读查询和一个状态。

## 代价和坑 {#costs-and-traps}

- **过期是按源文件算的**。如果对象 A 调用 B，只有 B 变了，列出的是 B 的卡片，不是 A 的。如果这次调用的含义变了，A 的卡片可能也要改。这会让调用方的卡片错多少次，我没有测过。只往下指、不照抄下层卡片内容的卡片，损失更小。地图本来就知道谁用了 B，所以一个便宜的办法是：把每张过期卡片的调用方都列为“可能过期”。我没有做过，也没有测过。
- **戳可能说谎**。它的价值只有它之前那次检查那么大。只给读过的卡片盖戳。定好谁有权盖戳，并记录下是谁盖的。你也可以让独立的 reviewer 对照代码，重读几张盖过戳的卡片，就像盲抽查那样（[8.3](8-3-kb-audit.html)）。
- **刷新必须有人负责**。清单显示什么过期了，它自己不会去修。
- **被拒绝的请求是损失，不是解决**。被拒绝的行仍然看得见，所以这个缺口是诚实的。
- **捕获可能让知识库塞满噪音**。上面的四个条件就是为了让它保持精简。

## 什么时候可以删掉 {#when-to-delete-it}

如果平台能追踪哪些存起来的笔记比它描述的代码更旧，就用平台的，去掉你自己的比较。给每条事实记下版本的习惯仍然适用。
