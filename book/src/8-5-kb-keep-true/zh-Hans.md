这一章接在[分批学一个领域](8-4-kb-learning.html)后面，是路线的第七步，而这一步永远做不完。笔记为什么一般都该带上来源和日期，[agent 该记住什么](3-5-memory.html)里讲过。落到代码上，这套习惯是什么样子，就是这一章要讲的。

## 一句话 {#in-one-sentence}

知识会过期，所以每张卡片都记下自己是在哪个 commit 读的。这样代码一变，就能列出过期的卡片，只修改动过的那几行。

## 写给管理者 {#for-leaders}

- **要拍板的事**：给知识库指定一个负责人，约定过期的笔记多久刷新一次，以及谁有权把一条笔记标成“已检查”。
- **风险**：一个曾经正确、之后再没检查过的知识库，可能比没有还糟，因为大家会信它。“已检查”的戳，只有它之前那次检查那么可靠。过期笔记的清单还会漏掉被改动对象的调用方，这会让多少笔记变错，我没有测过。
- **做对的代价**：每次刷新只读代码里改动的部分，不读整个文件，而且每个任务最多约 20 条笔记。列出过期笔记的清单，则完全不需要读任何东西。
- **可以问团队**：“我们有多少条笔记比它所描述的代码还旧，由谁负责？”

## 哪些卡片还是对的？ {#problem}

假设一个团队在三月写出了一批很好的卡片。到了六月，这些卡片所依据的文件已经改了三分之一。哪些卡片现在是错的，谁也说不清，于是读者对所有卡片都失去了信任，知识库要么没人看，要么更糟：错的卡片还有人信。

有两种应对办法，都不行。“隔一阵子全部重写一遍”，成本和第一次建库一样高。“指望大家发现卡片不对就顺手改掉”也行不通，因为大家根本发现不了。

既然这两条路都走不通，真正管用的，是让过期*看得见，而且花费很低*。只要卡片写明它读的是代码的哪个版本，脚本就能回答“什么动过了？”。这个思路不用任何工具也能试：记下一条笔记是在哪个 commit 读的，以后运行 `git diff <那个 commit>..HEAD -- <文件>`。diff 是空的，就说明这条笔记的来源没变。不过，要对整个知识库这样做，版本就得记在脚本读得到的地方。

## 让过期看得见，而且便宜 {#how-it-works}

### 卡片上的版本

那版本记在哪里？一共三个地方。头一个是**对象索引**，也就是脚本生成的一份清单，列出每个对象和它的源文件。（commit 和 sha 在[知识库：代码的诚实索引](8-1-why-a-knowledge-base.html)里讲过。）

- **对象索引的每一行**，保存写卡片时源文件的 sha。
- **每张卡片**带一个标记，说明它对照代码验证过、是在哪个 commit 读的。读者看这个标记，就知道这张卡片有没有对照代码检查过。
- **领域**按仓库记下它学习时所在的 commit。

### 列出过期的卡片

既然索引的每一行都有 sha，脚本就可以拿它和基线分支（代码的主线）上现在的文件比较。来源变了，卡片就**过期**了。来源被删除的卡片，也会列出来。

::: figure 8-5-stale-cards

这样一来，需要关注的只有变了的卡片，大代码库里的一个小改动，对应的也只是一份短清单。清单的长度占全部卡片的比例，就是该放上看板的数字。不过有一个缺口要知道：清单列出的是自己的来源变了的卡片，不包括调用方的卡片（见[清单漏掉了什么，哪些还得靠人](#costs-and-traps)）。

### 刷新：读 diff，不读文件

为什么不干脆把文件重读一遍？**diff**，也就是自卡片写成以来来源里改了什么，读起来更便宜，还能指出卡片里哪几行可能已经错了。

如果改动没碰到卡片说的内容（注释、格式、卡片没覆盖的部分），文字就保持不变；碰到了，agent 也只改被牵动的那几行。改完之后，agent 给卡片**盖戳**，记下这张卡片已经对照现在的代码检查过。戳是一种声明，所以只该盖在 agent 真正检查过的卡片上。要是给一张没人读过的卡片盖了戳，一张错卡片就会一直藏到下一次改动。

一次刷新和别的任务没什么两样：先有一份计划，列出每张卡片和预计要改什么，人审批了这份计划，再把结果写回（[两道门：人在哪里审批](5-3-two-approvals.html)）。一个任务最多约 20 张卡片，过期的更多，就先做用得最多的。

还有来源不见了的卡片，要多做一个决定。agent 先查文件是不是改了名，改名了就更新路径。如果文件被删了，agent 就去问人：这张卡片是删掉还是留着。留下的卡片会标成“来源已不在”，它的标记也变成*未知*，这样它读起来就不像检查过的知识。

### 做完的任务教会了什么

来源变了，并不是卡片出错的唯一原因。agent 在做任务的时候，也可能发现某张卡片是错的或者缺了，就一边干活，一边在任务的日志里记下来。等任务结束，另有一步（我叫它**捕获**）挑出值得留下的内容，**起草**出来交给人审批。没有任何东西会自己进知识库。“下个月还成立”只是模型的预测，所以人的审批才是真正的检查。

捕获只在下面这些条件同时满足时才留下一条：没有它，将来的 agent 会做错；任务里有证据（一个文件和行号）；知识库里还没有记录；下个月还会成立。“这里没有值得留的”也是一个好答案。该记什么的通用规则，在[agent 该记住什么](3-5-memory.html)里。

### 请求清单：代码说不出来的东西

捕获补上的，是 agent 干活时自己撞见的东西。有些东西它读代码再细也撞不见，因为它们根本不在代码里，而来自人和正在运行的系统（按我的估计只占一小部分，没有测过）。所以每个领域都有一份**请求清单**，人要提供的每样东西占一行。一行有：

- 一个**类别**：*code*（不在任何仓库里的源码）、*runtime*（某个环境里的值）、*history*（要到 git 里找的东西）或 *decision*（需要某个人做出的选择）；
- 一条只读的命令或查询，人可以原样运行；
- 一个**状态**：*open*（未处理）、*answered*（已回答，记下什么时候、谁回答的、填到了哪里）或 *declined*（已拒绝，之后不再问）。

这些行来自地图看不见的地方（[8.3](8-3-kb-audit.html)）：动态名字、外部名字、被删掉的来源。agent 在下一次停下来的时候提问，绝不在干活中途打断。

人给回来的东西写进第二个文件，叫**环境事实**，一行一条事实，比如某个作业有没有启用，某张规则表里有什么。每行记下环境、日期、对象、当天该对象代码的 sha，以及是谁提供的。这样代码往前走了之后，从那个 sha 就看得出，这条事实是对着更旧的代码看到的。不过，人贴回来的内容仍然是不可信的文本：里面可能有脏数据，甚至有指令，所以要照[agent 读到的文字可能在指挥它](4-6-untrusted-input.html)里的办法对待。

### 把已有的知识库接进来

如果你手上已经有关于代码的笔记，也可以改成这种格式。每个 sha 要设成旧笔记写成时的 commit，而不是今天的。这样从第一天起，过期清单就是诚实的，因为它显示的正是笔记写成以来变了什么。麻烦在于，旧笔记往往没写明出自哪个 commit，只能猜。猜错了，过期的卡片反倒被藏起来，所以这一步要比听起来难。

### 测一测你自己的配置

1. 拿三张卡片，写下各自是在哪个 commit 读的。
2. 改一个源文件，再列出来源变了的卡片。
3. 只按 diff 刷新，数一数你读了多少行，和整个文件比一比（`git diff --stat` 显示改了多少行；`wc -l` 显示文件有多少行）。
4. 往请求清单里加一行，写上类别、一条只读查询和一个状态。

## 清单漏掉了什么，哪些还得靠人 {#costs-and-traps}

过期是按源文件算的，所以清单本身就有一个缺口。如果对象 A 调用 B，而只有 B 变了，列出来的是 B 的卡片，不是 A 的；可要是这次调用的含义变了，A 的卡片也可能要改。这会让调用方的卡片错多少次，我没有测过。只往下指、不照抄下层卡片内容的卡片，损失会小一些。地图本来就知道谁用了 B，所以一个便宜的办法是把每张过期卡片的调用方都列为“可能过期”，不过这个办法我没有做过，也没有测过。

戳也可能说谎，因为它只有它之前那次检查那么可靠。所以只给读过的卡片盖戳，定好谁有权盖戳，并记录下是谁盖的。你也可以让独立的 reviewer 对照代码，重读几张盖过戳的卡片，就像审计（[8.3](8-3-kb-audit.html)）里那样。

剩下的不是清单的漏洞，而是只有人能做的事。刷新得有人负责，因为清单只显示什么过期了，自己什么也不修。被拒绝的请求是损失，问题并没有解决。不过被拒绝的那一行仍然看得见，所以这个缺口是诚实的。捕获也可能让知识库塞满噪音，上面那四个条件，就是为了让它保持精简。

## 什么时候可以删掉自己的比较 {#when-to-delete-it}

如果平台能追踪哪些存起来的笔记比它描述的代码更旧，就用平台的，把你自己的比较去掉。给每条事实记下版本的习惯，仍然适用。
