這一章接在 [分批學一個領域](8-4-kb-learning.html) 後面。它是路線的第七步，而且永遠不會結束。筆記為什麼一般來說該帶有來源和日期，見 [agent 該記住什麼](3-5-memory.html)；這一章說明它用在程式碼上是什麼樣子。

## 一句話 {#in-one-sentence}

知識會過期。所以每張卡片記下它讀的是哪個 commit，程式碼改了之後，你可以列出過期的卡片，只修改有變的那幾行。

## 給主管 {#for-leaders}

- **要做的決定**：為知識庫指定一位負責人，講好過期的筆記多久更新一次，以及誰可以把一則筆記標成已檢查。
- **風險**：曾經是對的、卻從沒檢查過的知識庫，可能比沒有還糟，因為人們會相信它。寫著「已檢查」的印章，只有它前面的那次檢查那麼可靠。過期筆記的清單，會漏掉被改動物件的呼叫者；我沒有測過這會讓多少筆記變錯。
- **做對的成本**：每次更新只讀程式碼裡改過的部分，不是整個檔案，在最多約 20 則筆記的任務裡進行。過期筆記的清單不用讀任何東西。
- **可以問團隊**：「我們有多少筆記比它描述的程式碼更舊，誰負責它們？」

## 問題 {#problem}

一個團隊在三月寫了很好的卡片。到了六月，它們來源的檔案有三分之一改過了。沒有人說得出現在哪些卡片是錯的。於是讀者對所有卡片都失去信任，知識庫被無視。曾經是對的、卻從沒檢查過的知識庫，可能比沒有還糟，因為它被人相信。

有兩種處理辦法都行不通。一種是「時不時全部重寫」：成本和第一次建一樣。另一種是「希望人們注意到時就修卡片」：他們不會注意到。

解法是讓過期*看得見、又便宜*。卡片精確地說它讀的是程式碼的哪個版本，然後腳本就能回答「什麼動過了？」你不用任何工具也可以試這個想法：寫下一則筆記讀的是哪個 commit，之後執行 `git diff <那個 commit>..HEAD -- <那個檔案>`。如果 diff 是空的，筆記的來源就沒有變。

## 原理 {#how-it-works}

### 卡片上的版本

commit 和 sha 在 [知識庫：程式碼的誠實索引](8-1-why-a-knowledge-base.html) 解釋過。**物件索引**是腳本建出來的清單，列出每個物件和它的原始檔案。

有三個地方記著版本：

- **物件索引的每一行**，保留寫卡片時原始檔案的 sha。
- **每張卡片**帶有一個標記，說明它已對照程式碼驗證過，以及它讀的是哪個 commit。這個標記告訴讀者，卡片有沒有對照程式碼檢查過。
- **領域**記下它學的時候，每個倉庫的 commit。

### 列出過期的卡片

腳本把每一行索引上的 sha，和基底分支（程式碼的主線）上現在的檔案比較。來源改了的卡片就**過期**。來源被刪掉的卡片也列出來。

::: figure 8-5-stale-cards

只有改過的卡片需要注意，所以大程式碼庫裡的小改動，清單就很短。過期卡片的比例，也是適合放在看板上的數字。要知道一個缺口：清單列出的是自己的來源改過的卡片，不是它們的呼叫者的卡片（見 [代價和陷阱](#costs-and-traps)）。

### 更新：讀 diff，不讀檔案

對每張過期的卡片，agent 讀的是 **diff**：卡片寫好之後，來源到底改了什麼。這比重讀檔案便宜，而且它指出卡片裡可能錯的那幾行。

- 如果改動沒碰到卡片說的內容（註解、格式、卡片沒涵蓋的部分），文字就保持不變。
- 如果碰到了，agent 只改它碰到的那幾行。
- 然後它**蓋章**：記下這張卡片已對照現在的程式碼檢查過。印章是一個宣稱，所以只用在 agent 真的檢查過的卡片上。給沒人讀過的卡片蓋章，會把一張錯的卡片藏到下一次改動。

更新是一個和其他任務一樣的任務：一份列出每張卡片和預期改什麼的計劃、人的批准，然後寫回（[兩道門：人在哪裡批准](5-3-two-approvals.html)）。每個任務最多約 20 張卡片；更多的話，先做最常用的。

**來源不見的時候**，agent 先找有沒有改名。如果改名了，就更新路徑。如果被移除了，agent 問人，要丟掉這張卡片還是留著。留下的卡片會標成「來源已不在」，它的標記變成*未知*，這樣它讀起來就不像檢查過的知識。

### 做完的任務教了什麼

卡片還有另一種出錯的方式：做任務的時候，agent 發現一張卡片是錯的或缺的。它工作時把這點記在任務的紀錄裡。任務結束時，另一個步驟（我叫它**擷取**）挑出值得留下的，並**起草**給人批准。沒有任何東西會自己進知識庫。「下個月還是對的」只是模型的預測，所以人的批准才是真正的檢查。

只有在以下全部成立時，它才留下一項：沒有它，未來的 agent 會做錯；任務裡有證據（一個檔案和行號）；它還沒被記錄過；下個月還會是對的。「這裡沒有值得留下的」是個好答案。要記住什麼的一般規則，在 [agent 該記住什麼](3-5-memory.html)。

### 請求清單：程式碼說不出的

照我自己的猜測（不是量測），知識庫有一小部分不能來自程式碼。它來自人和正在執行的系統。所以每個領域有一份**請求清單**：每件必須由人提供的事，一列。一列有：

- 一個**種類**：*code*（一個不在任何倉庫裡的來源）、*runtime*（某個環境的值）、*history*（要在 git 裡找的東西），或 *decision*（某人必須做的選擇）；
- 一個唯讀的指令或查詢，人可以原樣執行；
- 一個**狀態**：*open*、*answered*（什麼時候、誰、放到哪裡去了），或 *declined*（之後就不再問）。

agent 在下一個停下來的地方問，從不在工作到一半時問。這些列來自地圖看不見的地方（[8.3](8-3-kb-audit.html)）：動態的名字、外部的名字、被刪掉的來源。

回來的東西，進入第二個檔案，**環境事實**：一列一個事實，例如某個工作是否啟用，或一張規則表裡有什麼。每一列有環境、日期、物件、當天它的程式碼的 sha，以及誰提供的。程式碼往前走之後，你看得出這個事實，是對照比較舊的程式碼看到的。人貼回來的東西，仍然是不可信的文字：可能有髒資料，甚至有指令，所以要像 [agent 讀到的文字可能在指揮它](4-6-untrusted-input.html) 那樣處理。

### 把你已有的知識庫帶進來

如果你已經有關於程式碼的筆記，可以搬成這個形式。把每個 sha 設成舊筆記寫的那個 commit，不是今天。這樣過期清單從第一天起就是誠實的：它顯示筆記寫好之後改了什麼。舊筆記常常沒說它們來自哪個 commit；那你就得猜，而猜錯會把過期的卡片藏起來。預期這比聽起來難。

### 測你自己的設定

1. 拿三張卡片。寫下每一張讀的是哪個 commit。
2. 改一個原始檔案。列出來源改過的卡片。
3. 只從 diff 更新。算一算，你讀的行數和整個檔案比起來是多少（`git diff --stat` 顯示改了的行；`wc -l` 顯示檔案）。
4. 在請求清單加一列，附上種類、一個唯讀的查詢和一個狀態。

## 代價和陷阱 {#costs-and-traps}

- **過期是以原始檔案為單位**。如果物件 A 呼叫 B，而只有 B 改了，B 的卡片會列出來，A 的不會。如果那個呼叫的意思變了，A 的卡片可能也需要改。我沒有測過這會讓多少呼叫者的卡片變錯。只往下指、不複製下層卡片內容的卡片，損失比較小。地圖已經知道誰用 B，所以一個便宜的修法，是把每張過期卡片的呼叫者列為「可能過期」。我沒有做過或測過這個。
- **印章可能說謊**。它的價值，只有它前面的檢查那麼好。只蓋你讀過的。決定誰可以蓋章，並記下是誰蓋的。你也可以讓獨立的 reviewer，像抽查那樣（[8.3](8-3-kb-audit.html)），對照程式碼重讀幾張蓋了章的卡片。
- **必須有人負責更新**。清單顯示什麼過期了。它自己不修任何東西。
- **被拒絕的請求是損失，不是解法**。被拒絕的列仍然看得見，所以缺口是誠實的。
- **擷取可能讓知識庫塞滿雜訊**。上面的四個條件，就是為了讓它保持小。

## 什麼時候可以刪掉 {#when-to-delete-it}

如果平台會追蹤哪些存下來的筆記比它描述的程式碼舊，就用它，放掉你自己的比較。每個事實都記下一個版本的習慣，仍然適用。
