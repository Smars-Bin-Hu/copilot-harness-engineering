Read this first

Checked: 2026-10-27. I read the official docs of VS Code, Claude Code and Codex on that day. Names, folders, settings and preview labels change often, so this page will go stale. Trust the docs over this table, and check the date.

Two things to know before reading the rows.

  • VS Code now asks you to choose a harness first. The VS Code docs say the harness you pick (for example the Copilot harness or the Local harness) decides which formats and locations work: "Creating a file doesn't mean the selected harness can load or run it." Some rows below say "Local harness only" for this reason.
  • "Enforced" has one meaning here. A thing is enforced if the platform makes the agent obey it, so the model cannot choose otherwise. Almost every row is a request to the model. The exceptions are a hook that refuses a call, and a tool list that removes tools. Why this matters is the subject of A rule in a prompt is a request.

Where I could not confirm a counterpart on the official pages, the cell says "not confirmed". I did not guess.

A quick guide to the rows:

  • A rule for every task: always-on instructions.
  • A rule for some files: instructions by file.
  • A way of working the agent starts when it fits: a skill.
  • A different set of tools or a read-only helper: a custom agent.
  • Something that must be refused: a hook, or taking the tool away.

先讀這個

確認日期：2026-10-27。我在那一天讀了 VS Code、Claude Code 和 Codex 的官方文件。名稱、資料夾、設定和 Preview 標籤常常改，所以這一頁會過期。文件比這張表可信，也請看一下日期。

讀這些列之前，先知道兩件事。

  • VS Code 現在要你先選一個 harness。VS Code 文件說，你選的 harness（例如 Copilot harness 或 Local harness）決定哪些格式和位置行得通：「建立一個檔案，不代表選定的 harness 能載入或執行它。」下面有些列因此寫著「只有 Local harness」。
  • 這裡的「強制」只有一個意思。平台讓 agent 必須服從的東西，模型不能選擇不照做，才算強制。幾乎每一列都是對模型的請求。例外是拒絕呼叫的 hook，和移除工具的工具清單。為什麼這很重要，是 提示裡的規則只是請求 的主題。

官方頁面上我確認不了對應項目的地方，格子裡寫「未確認」。我沒有猜。

各列的快速指南：

  • 每個任務都適用的規則：永遠載入的指令。
  • 只對某些檔案適用的規則：依檔案的指令。
  • agent 在合適時啟動的做法：skill。
  • 不同的一組工具，或唯讀的幫手：custom agent。
  • 必須被拒絕的事：hook，或把工具拿掉。

How to use this page

Two habits make this table useful.

  • Put a rule in the lightest point that is enough. Always-on instructions cost room every turn; a skill costs room only when used; a hook costs code. The order and the reasoning are in Context is a budget and A rule in a prompt is a request.
  • Check the harness before the file. If a file seems ignored, first ask whether the harness you selected can load that kind of file at all. Troubleshooting starts from symptoms.

The examples in this book come from one setup on the Copilot side. I have not run the Claude Code and Codex columns myself; they come from the vendors' docs on the date above.

怎麼用這一頁

兩個習慣讓這張表有用。

  • 把規則放在夠用的最輕的那一點。永遠載入的指令每一輪都占空間；skill 只在用到時占空間；hook 花的是程式碼。順序和推理在 上下文是一份預算 和 提示裡的規則只是請求。
  • 先查 harness，再查檔案。如果一個檔案好像被忽略，先問你選的 harness 到底能不能載入這種檔案。排錯 從症狀開始。

這本書的例子，都來自 Copilot 這一邊的一套設定。Claude Code 和 Codex 的欄位我自己沒有執行過；它們來自廠商在上面那個日期的文件。
