Before you rely on a row

Checked: 2026-10-27. That is the day I read the official docs of VS Code, Claude Code and Codex for this page. Names, folders, settings and preview labels change often, so the page will go stale. That is why the date is here: check it before you lean on a row. If the table and the docs disagree, the docs win.

Two more things decide how you read the rows.

  • VS Code now asks you to choose a harness first. Here "harness" is VS Code's own name for the option you pick, such as the Copilot harness or the Local harness, and according to the VS Code docs that choice decides which formats and locations work. In their words, "Creating a file doesn't mean the selected harness can load or run it." That is why some rows below say "Local harness only".
  • "Enforced" has one meaning here. A thing is enforced if the platform makes the agent obey it, so that the model cannot choose otherwise. By that measure almost every row is a request to the model. The exceptions are a hook that refuses a call and a tool list that removes tools. Why the difference matters is the subject of A rule in a prompt is a request.

If you know what you want but not which row it belongs to, start here:

  • A rule for every task: always-on instructions.
  • A rule for some files: instructions by file.
  • A way of working the agent starts when it fits: a skill.
  • A different set of tools or a read-only helper: a custom agent.
  • Something that must be refused: a hook, or taking the tool away.

How to use this page

Two habits make this table useful.

  • Put a rule in the lightest point that is enough. Always-on instructions cost room every turn, a skill costs room only when it is used, and a hook costs code. The order and the reasoning are in Context is a budget and A rule in a prompt is a request.
  • Check the harness before the file. If a file seems to be ignored, first ask whether the harness you selected can load that kind of file at all. If the harness is not the cause, Troubleshooting starts from the symptom you see.

怎麼用這一頁

有兩個習慣，能讓這張表派上用場。

  • 把規則放在夠用的、最輕的那一點。這幾個點分量不同：永遠載入的指令每一輪都占空間，skill 只在用到時才占，hook 要花的是寫程式碼的功夫。誰輕誰重、為什麼，見 上下文是一份預算 和 提示裡的規則只是請求。
  • 先查 harness，再查檔案。一個檔案好像被忽略了，先問問你選的 harness 到底能不能載入這種檔案。如果問題不出在 harness 上，排錯 會從你看到的症狀查起。

怎么用这一页

有两个习惯，能让这张表派上用场。

  • 规则放在够用的、最轻的那个点上。这几个点分量不同：始终开启的指令每一轮都占地方，skill 只在用到时才占，hook 要花的是写代码的功夫。谁轻谁重、为什么，见为什么不能把所有规则都塞给 Agent？和为什么 Agent 不听 prompt 里的规则？。
  • 先查 harness，再查文件。一个文件好像被忽略了，先问问你选的 harness 到底能不能加载这类文件。如果问题不出在 harness 上，Agent 出问题了，先查哪里？会从你看到的症状查起。
